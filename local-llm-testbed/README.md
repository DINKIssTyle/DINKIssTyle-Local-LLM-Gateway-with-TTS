# Local LLM Code Testbed

로컬 OpenAI 호환 LLM으로 실제 대화를 실행한 뒤 그 결과를 별도 분석하고, 선택적으로 코드를 수정하고 테스트까지 실행하는 독립형 웹 앱입니다. 기존 채팅 서버와 별도 포트 및 프로세스로 실행됩니다.

실행 흐름은 다음과 같습니다.

1. `실제 대화 테스트 질의`를 앱과 동일한 스킬·웹 도구 경로로 실행합니다.
2. 응답, 선택된 스킬, 도구 인자, 오류와 출처를 구조화된 보고서로 만듭니다.
3. 분석 에이전트가 실제 보고서를 근거로 원인을 판단합니다.
4. 권한이 켜져 있고 실제 문제가 확인된 경우에만 코드를 수정하고 테스트합니다.

따라서 일반 대화 문장은 코드 수정 지시가 아니라 먼저 실제 대화 입력으로 처리됩니다. 저장소의 `scenarios.json`은 회귀 테스트 데이터일 뿐 분석 에이전트의 실행 지침으로 취급되지 않습니다.

## 실행

저장소 루트에서:

```sh
./run-local-llm-testbed.sh
```

기본 브라우저가 `http://127.0.0.1:31987`을 엽니다. 자동으로 브라우저를 열지 않으려면:

```sh
./run-local-llm-testbed.sh -no-open
```

독립 실행 파일도 만들 수 있습니다.

```sh
go build -o build/local-llm-testbed ./cmd/local-llm-testbed
```

## 연결 설정

- LM Studio 기본 예시: `http://127.0.0.1:1234/v1`
- llama.cpp 예시: 서버가 OpenAI 호환 `/v1/chat/completions`와 `/v1/models`를 제공하도록 실행
- API 키는 로컬 서버가 요구할 때만 입력하며 브라우저 저장소에 보관하지 않습니다.
- 안전을 위해 LLM 엔드포인트는 loopback 주소만 허용합니다.

## 모드와 권한

- `문제 진단`: 파일 목록, 텍스트 검색, 파일 읽기만 제공합니다.
- `진단 및 수정`: `파일 수정 허용`을 추가로 켜면 정확한 텍스트 교체와 새 파일 생성 도구가 제공됩니다.
- `테스트 명령 허용`: 셸을 거치지 않고 제한된 테스트·빌드·검사 명령만 실행합니다.

허용되는 명령 계열은 다음과 같습니다.

- `go test`, `go vet`, `go build`
- `npm test`, `npm run test|build|lint`
- `git status|diff|grep|log`
- `rg`
- `cargo test|check|build`
- `swift test|build`
- `python -m pytest|unittest`

임의 셸 명령, 삭제 명령, 네트워크 명령, Git 쓰기 명령은 제공되지 않습니다.

## 안전 경계

- 파일 경로는 선택한 작업 폴더 내부로 제한됩니다.
- 절대 경로, `..` 탈출, 외부를 가리키는 심볼릭 링크를 거부합니다.
- 파일 교체는 기존 문자열이 정확히 한 번 일치할 때만 수행합니다.
- 새 파일 생성은 기존 파일을 덮어쓰지 않습니다.
- 동시에 하나의 에이전트 실행만 허용합니다.
- 쓰기 실행 전 UI에서 한 번 더 확인합니다.

중요한 저장소에서는 실행 전에 커밋하거나 별도 작업 트리를 사용하는 것을 권장합니다.
