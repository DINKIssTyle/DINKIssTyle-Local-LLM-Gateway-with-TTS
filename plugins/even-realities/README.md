# DKST AI Gateway — Even G2

G2용 Even Hub 웹 앱입니다. 휴대폰 Even Realities 앱에서 실행하고 G2의 화면·마이크·터치 입력을 연결합니다. 일반 브라우저에서는 설정과 화면 미리보기를 사용할 수 있으며 G2 녹음은 Even 앱 안에서만 가능합니다.

## 2.7.2 — 컴팩트 표시·전사문 숨기기

폰 설정과 안경 메뉴에 **전사문 숨기기**를 추가했습니다. 기본은 표시이며 선택은 앱 저장소에서 복원합니다. AI 모드의 화면 표시만 바꾸므로 마이크 재시작 없이 즉시 적용되고, STT·전사 저장·힌트 판단은 계속됩니다. 번역의 예상 답변은 숨기지 않습니다. 전사와 힌트가 모두 없을 때도 상단 상태줄의 이벤트 캡처로 탭/메뉴를 사용할 수 있습니다. 전사를 숨기면 긴 힌트 본문은 최대 8줄까지 공간을 사용하되 짧은 힌트는 계속 내용 높이만 사용합니다.

전사는 최대 3줄로 유지하면서 AI 박스의 최대 높이 강제 배정을 제거했습니다. 힌트가 없으면 박스를 숨기고 상단 상태줄 바로 아래에서 전사를 표시합니다. 힌트가 있으면 제목 1줄+실제 본문 줄 수만큼 박스를 만들고, 그 바로 아래에 최대 3줄의 전사를 배치합니다. 아래쪽 남는 캔버스는 비워 둡니다. 직접 AI 답변도 실제 줄 수만큼만 높이를 사용합니다. 물리 화면/SDK 캔버스 해상도는 그대로이며 밝게 표시되는 영역만 작아집니다.

AI 힌트는 제목+본문 최대 5줄까지 늘어나고 초과 본문은 제목을 고정한 채 스크롤합니다. 예: 힌트 없음은 상태줄+전사 최대 108px, 제목+내용 1줄은 최대 168px, 제목+내용 3줄은 최대 222px입니다. 휴대폰 미리보기의 고정 전체 높이도 제거했습니다. 번역 모드는 유지합니다.

검증: 대기 상태 박스 숨김·짧은/긴 힌트와 직접 답변의 내용 높이·전사 3줄 제한·숨김 상태에서 저장/녹음 유지·폰/안경 선택과 설정 복원·입력 소스별 메뉴 10개 제한·숨긴 대기 화면의 탭 캡처·사용하지 않는 하단 여백·같은 높이의 내용 갱신·SDK 경계 검사와 전체 플러그인 회귀 테스트를 통과했습니다. 안경 앱만 업데이트하며 게이트웨이 재시작은 필요 없습니다.

## 2.7.1 — 전사 최대 3줄·나머지 AI 영역

AI 모드의 전사 표시를 항상 하단 3줄(81px) 이하로 제한합니다. 상단 상태 27px를 제외한 나머지 180px는 AI 박스가 모두 사용합니다. 대기 중에도 전사 영역을 늘리지 않으며, 힌트 길이가 바뀌어도 본문 컨테이너를 재배치하지 않습니다. 제목 1줄과 본문 최대 5줄을 표시하고 긴 본문은 제목을 유지한 채 스크롤합니다. 직접 AI 답변은 같은 영역에서 6줄을 표시합니다. 번역 모드의 예상 답변 4줄은 전사 영역이 아니므로 유지합니다. 휴대폰 미리보기도 전사 표시 높이를 최대 3줄로 제한했습니다.

검증: 대기·짧은/긴 힌트에서 전사 3줄 한도, AI 180px 배정, 제목 고정 스크롤, 캔버스 경계·SDK 검증·동일 배치 갱신과 전체 플러그인 회귀 테스트를 통과했습니다. 안경 앱만 업데이트하며 게이트웨이 재시작은 필요 없습니다.

## 2.7.0 — 힌트 제목·내용과 자동 높이

안경 앱만 2.7.0으로 업데이트하면 적용됩니다. 이번 화면 수정에 게이트웨이 추가 재시작은 필요 없습니다.

- AI 자동 힌트에 기존 선별 주제를 제목으로 표시하고, 다음 줄부터 정보 본문을 표시합니다. 별도 제목 생성 LLM 요청은 하지 않습니다. 제목은 안경 글꼴 폭으로 한 줄에 맞춰 말줄임하며, 긴 내용 스크롤에서도 제목을 유지합니다. 힌트 중복 비교·저장에는 제목을 섞지 않습니다.
- 지원되는 576×288 캔버스에서 상단 27px는 그대로 둡니다. 힌트가 없으면 빈 박스를 제거하고 전사가 남은 261px(9줄)를 사용합니다. 완료된 힌트는 제목 1줄+본문 실제 1~6줄+테두리/패딩에 맞춰 60~195px로 조절합니다. 전사는 나머지 공간을 즉시 사용하며 최소 2줄을 남깁니다. 예: 제목+본문 1줄은 전사 7줄, 제목+본문 3줄은 전사 5줄, 제목+본문 6줄은 전사 2줄입니다.
- SDK의 텍스트 갱신에는 좌표/크기 변경 기능이 없어, 줄 수가 달라질 때만 같은 전송 큐에서 페이지를 재배치합니다. 같은 높이의 새 힌트는 내용만 갱신합니다. 전사 프리뷰 토큰마다 재배치하지 않으며 설정 목록이 열려 있는 동안에는 표시 갱신을 보류합니다. 빈 박스가 없을 때 터치 입력은 전사 컨테이너가 받습니다.
- 휴대폰 미리보기에도 실제 힌트 제목과 남는 전사 공간을 반영합니다. 직접 AI 채팅 답변과 번역 모드의 기존 배치는 유지합니다. 새 힌트를 만드는 중에는 마지막으로 표시한 제목·내용·높이를 유지합니다.

검증: 실제 생성 페이지 전체를 SDK 검증기에 통과시키고, 제목+본문 순서·한 줄 제목 폭·1~6줄 높이·최소 전사 2줄·본문 빈 상태 9줄·캔버스 경계·없는 컨테이너에 대한 갱신 방지·동일 높이에서 재배치 생략과 전체 플러그인 회귀 테스트를 확인했습니다. 앱이 만든 HTML과 실제 CSS로 4개 높이의 휴대폰 미리보기도 렌더링해 확인했습니다. G2에서 재배치 시 화면 깜박임 여부는 실기 확인이 필요합니다.

## 2.6.0 — 독립 LLM 힌트 판별·짧은 문맥·중첩 JSON 수정

안경 앱 2.6.0과 이번 Mac 게이트웨이를 함께 업데이트하고 게이트웨이를 완전히 종료한 뒤 다시 실행합니다.

- 역할별 모델에 **AI 힌트 판별**을 추가했습니다. 최신 전사에서 주제·원문 근거·독립적인 조사 항목·정보 경로만 JSON으로 고릅니다. 실제 정보 작성은 기존 **AI 힌트** 모델입니다. `기본 모델 사용`은 기본 모델을 따르며, `사전·JEV만 사용`으로 이전 방식도 선택할 수 있습니다. 선택과 문맥 한도는 Even 앱 저장소에 보존됩니다.
- 처음에는 서버 목록에 있는 **Gemma 4 E2B**를 추천 선택합니다. 직접 선택한 값은 이후 모델 목록 갱신으로 변경하지 않습니다. Qwen3.5 0.8B도 선택 가능하지만 이번 합성 전사 비교에서는 잘못된 생략·원문 근거 생성이 있어 자동 추천하지 않습니다. 같은 모델을 판별과 작성에 함께 할당할 수 있어 추가 상주 모델이 필수는 아닙니다. 모델을 자동 다운로드하지 않습니다.
- **힌트 판별 문맥 300~800토큰, 기본 600**을 선택합니다. 한국어를 영문처럼 글자 수/4로 계산하지 않고 보수적인 다국어 추정치로 제한합니다. 최신 전사 우선으로 짧은 이전 문맥·최근 표시 사실·명칭 후보를 배분합니다. 이 설정은 전사/참고 문맥 예산이며 고정 시스템 지침·JSON 스키마·출력은 별도입니다. 모델별 정확한 토크나이저 한도는 아니며 상태에 추정 사용량을 표시합니다. 전체 전사 기록이나 웹 채팅 기록을 판별기에 주입하지 않습니다.
- 사전·JEV는 선택적 참고입니다. 부정 판정·사용 중·설정 비활성·오류·350ms 이상 지연이어도 전사 자체를 LLM이 판별합니다. 판별 LLM 오류 때는 이미 받은 긍정 JEV 후보만 이전 경로로 처리하고, 그렇지 않으면 새 발화로 넘어갑니다. 정상적인 LLM 생략을 JEV가 뒤집지는 않습니다.
- 모델 출력의 근거가 실제 전달한 최신 원문 안에 있어야 채택합니다. 판별기가 사실이나 답변을 써서 바로 표시하는 경로는 없으며, 조사 계획을 기존 근거 조회/힌트 작성으로 넘깁니다. 큰 모델로 같은 계획을 다시 만드는 요청은 생략합니다. 웹·기억 자료는 기존 읽기 전용 조회와 사용자 설정을 따릅니다.
- 판별은 3초 간격으로 최신 작업 하나만 유지합니다. 답변 작성/AI 채팅 중에는 판별을 미루고 최신 발화를 보관합니다. 마이크·STT는 기다리지 않습니다. 클라이언트 판별 시간은 4.5초, 서버는 6초, 출력은 192토큰으로 제한합니다. 판별은 서버의 대화 모드와 관계없이 stateless `/v1/chat/completions`를 쓰며 도구·기억·일반 런타임 프롬프트·자동 리즈닝 재시도 없이 처리합니다. 추론 끄기 요청을 보내며 추론 채널만 온 결과는 표시하지 않습니다.
- 모델이 `{"result":"{...JSON...}"}` 형태로 한 번 더 감싼 출력도 제한된 깊이로 해제합니다. 기존 계획/정보 메모와 새 판별 양쪽에 적용해 로그에서 확인된 누락 형식을 고쳤습니다.

검증: 설치된 Qwen3.5 0.8B와 Gemma 4 E2B를 같은 5개 합성 전사로 비교했습니다. Gemma는 피라미드·청동기 시대·맥북 에어 M4·CRISPR를 선택하고 일상 인사는 생략했으며, 로딩 후 0.6~1.1초, 입력 533~549토큰이었습니다(실제 대화에서의 정확도를 보장하는 수치는 아님). 문맥 예산·원문 검증·중첩 JSON·취소/시간 초과·JEV 부정 판정 우회·작성 모델 분리·중복 계획 생략·오류 중 녹음 유지와 전체 Go/플러그인 회귀 테스트를 확인했습니다.

## 2.5.1 — Apple 엔진 메뉴 누락 수정

안경의 번역 엔진·음성 인식 엔진 목록에서 Apple 항목을 항상 표시합니다. 비동기 지원 여부 확인 전의 휴대폰 `<option disabled>` 상태로 항목을 숨기던 동작을 제거했습니다. Apple 지원 여부 조회도 모델 목록의 성공 여부와 분리했습니다. 지원하지 않는 서버·OS에서는 기존 엔진 준비 오류와 STT 대체 엔진 안내를 사용합니다. 안경 앱만 업데이트하면 적용되며 게이트웨이 추가 재시작은 필요 없습니다.

검증: Apple 옵션이 비활성 상태여도 두 네이티브 목록에 Apple이 표시되는지, 모델 목록 요청이 실패해도 Apple 지원 여부를 조회하는지 및 전체 플러그인 회귀 테스트를 확인했습니다.

## 2.5.0 — 안경 설정 메뉴·녹음 중 변경·사전 기반 힌트 후보

안경 앱 **2.5.0**과 이번에 빌드한 Mac 게이트웨이를 함께 사용합니다. 게이트웨이는 완전히 종료한 뒤 다시 실행해야 새 로컬 사전·JEV 경로가 적용됩니다.

- 안경 메뉴에 기존 화면과 같은 **인식 언어 / 번역 언어 / 번역 엔진 / 음성 인식 엔진 / 내 목소리 제외**를 추가했습니다. 안경 입력일 때 **안경 입력 감지 민감도**도 표시합니다. SDK의 단일 단계 메뉴에서 네이티브 목록 화면을 열며 스크롤은 선택 위치만 이동하고 탭으로 적용합니다. 길게 누르거나 메뉴의 돌아가기로 취소합니다. Apple 미지원 서버에서는 Apple 항목을 제외합니다.
- 폰·안경 모두 녹음 중 이 설정을 변경하면 현재 음성을 마무리하고 마이크 종료 확인 → 설정 저장·엔진 준비 → 이전에 녹음 중이었다면 재개합니다. STT 선택을 녹음 중에도 사용할 수 있습니다. 같은 값은 재시작하지 않으며 연속 변경은 마지막 값으로 합칩니다. 준비 중 녹음 버튼을 누르면 자동 재개를 취소합니다. 마이크 종료가 확인되지 않으면 새 마이크를 열지 않습니다. 대기 중 변경은 녹음을 시작하지 않습니다.
- 변경 전에 대기/처리 중이던 음성의 엔진·언어를 덮어쓰거나 저장 요청을 취소하지 않습니다. 전사 결과는 저장하되 새 설정의 번역·힌트에는 보내지 않습니다. AI 모드의 기존 지연 음성 폐기 정책은 유지합니다. 번역 결과·예상 답변은 같은 모드에서 설정을 바꿔도 다음 결과가 올 때까지 유지합니다.
- `내 목소리 제외`는 기존처럼 번역 모드에 적용합니다. 화자 구분이 없는 입력에서는 자신을 식별할 수 없습니다. 안경 감도는 소프트웨어 감지 기준이며 하드웨어 마이크 게인 조절이 아닙니다. 증폭은 기존처럼 녹음을 멈춘 뒤 폰에서 변경합니다.
- 한국어 위키백과 공개 문서 제목을 정리한 **1,325,725개 로컬 명칭 사전**을 게이트웨이에 포함했습니다. 본문이나 추가 모델은 없습니다. 복합 명칭·조사 부착형을 사전과 대조하되 완전한 단어 일치를 우선하고, 알려진 명칭에만 조사를 분리합니다. 원문 표현·문장 증거를 보존하고 최대 6개 후보를 기존 EmbeddingGemma 2 + JEV가 판단합니다. 이미 표시한 사실도 참고하며, 유용한 후보가 없거나 사전에 없는 명칭은 기존 문장 판단 경로를 사용합니다. 선택된 명칭과 원문은 설정된 힌트 LLM의 새 정보 탐색에 함께 전달합니다.
- 사전은 압축 약 12.2MB이며 최초 사용 시 한 번 펼칩니다. 빌드·실행 시 사전/모델을 자동 다운로드하지 않습니다. 출처·재생성 방법은 `internal/core/data/README.md`에 기록했습니다. 사전은 주제 후보 추출용이며 사실의 근거나 위키백과 문서 검색 결과로 취급하지 않습니다.

검증: 로컬 JEV로 피라미드·청동기 시대·EBITDA·맥북 에어 M4를 선별하고 일상 대화는 생략하는지 확인했습니다. 조사/복합 명칭·원문 증거·표시한 사실 전달, 네이티브 목록 스크롤/선택·SDK 제한, 설정 변경 시 마이크 종료/재개·동일 값/빠른 변경/수동 중지·이전 음성 보관과 전체 Go/플러그인 회귀 테스트를 확인했습니다. 실제 G2 메뉴 조작과 음성 품질은 기기에서 확인해야 합니다.

## 2.4.0 — 안경 입력 감지 민감도·선택적 증폭

현재 안경 패키지는 **2.4.0**입니다. 안경 앱 업데이트로 적용되며 게이트웨이 추가 재시작은 필요 없습니다.

- 안경 입력에 `표준 / 높음 / 매우 높음` 감지 민감도와 `없음(1배) / 2배 / 4배` 소프트웨어 증폭을 추가했습니다. 기본은 **높음 + 1배**입니다. 감지 RMS 기준은 각각 0.008 / 0.004 / 0.002이며 이전 설정도 새 기본값인 0.004를 사용합니다. `표준`을 선택하면 이전 기준으로 돌아갑니다. 모든 STT 엔진의 공통 입력 단계에 적용합니다.
- 휴대폰 입력은 PCM을 비트 단위로 보존하고 기존 감지 기준 0.008을 사용합니다. 안경 설정은 휴대폰 선택 시 숨기며 다시 안경으로 돌아오면 저장한 값을 사용합니다. 설정은 앱 저장소에서 복원되고 녹음 중에는 변경을 잠급니다.
- 감지 판정은 증폭 전 음량을 사용하여 증폭만으로 잡음이 발화 구간으로 판정되지 않도록 했습니다. STT에 보내는 새 PCM 프레임은 한 번만 증폭하고 이후 누적 프리뷰를 다시 증폭하지 않습니다. 큰 입력은 프레임 전체의 증폭률을 낮춰 새 정수 클리핑을 방지합니다. 증폭 없음과 휴대폰 입력은 원본 버퍼를 수정하지 않습니다.
- 입력 음량 표시에서 수신/적용 후 dBFS, 감지 기준 통과 여부, 큰 소리 증폭 제한을 확인합니다. 화자 필터에서 제외한 음성은 음량이 수신되어도 전사 구간에 넣지 않으며 화면에는 `화자 필터로 제외`라고 표시합니다. 음량 표시는 약 150ms 간격으로 갱신합니다.
- SDK에서 안경의 하드웨어 게인을 조절하는 기능은 아닙니다. 이미 안경·Even 앱 단계에서 제거된 음성을 복원하거나 신호 대 잡음비를 새로 높이지는 못합니다. Whisper의 기존 서버 말소리 필터는 별도로 유지합니다.

검증: 합성 PCM으로 기존 기준 미만의 입력을 새 기준에서 보존하는지, 2배 증폭·프레임 최대값 보호·미리보기 중복 증폭 방지·화자 제외 유지, 안경 설정 최대 상태에서도 휴대폰의 원본 PCM과 감지 기준이 유지되는지, 설정 복원·녹음 중 변경 잠금 및 전체 앱 회귀 테스트를 통과했습니다. 390px 폭의 설정 영역 배치도 확인했습니다. 실제 G2에서의 전사 정확도 향상은 기기에서 비교해야 합니다.

## 2.3.1 — 상단 아이콘 순서와 휴대폰 마이크 권한

현재 안경 패키지는 **2.3.1**입니다. 안경 앱 업데이트로 적용되며 게이트웨이 추가 재시작은 필요 없습니다.

- AI 상단을 `[AI <호출어 아이콘> 키워드] <마이크모드 아이콘> | 메시지` 순서로 수정했습니다. 번역 모드도 언어 방향 다음에 마이크모드 아이콘을 배치합니다. 이전 순서는 SDK 제약이 아닌 앱의 배치 선택이었습니다.
- 텍스트와 이미지 컨테이너를 나누고 펌웨어 글꼴의 실제 폭으로 위치를 계산합니다. AI는 텍스트 6개+이미지 2개, 번역은 텍스트 5개+이미지 1개로 SDK 한도 안에 있습니다. 키워드·언어 방향이 바뀔 때만 위치를 다시 배치하며, 메시지 스트리밍·마이크 상태만 바뀔 때는 내용만 갱신합니다. 긴 키워드는 말줄임 처리합니다.
- 누락된 `phone-microphone` 패키지 권한을 추가했습니다. 기존 `g2-microphone` 권한도 유지합니다. SDK native Phone 입력을 사용하며 별도의 getUserMedia/Web Audio 마이크를 열지 않습니다. iOS의 Even 앱 마이크 허용은 별도로 필요합니다. 권한 추가만으로 사용자가 보고한 첫 화면 탭 현상까지 해소되는지는 실기 확인이 필요합니다.
- 휴대폰 소스가 열렸다고 응답했지만 PCM이 오지 않으면 입력을 정지하고 iOS 권한 확인·휴대폰 녹음 버튼 재시작 안내를 유지합니다. 안경 연결 오류로만 안내하지 않습니다.

검증: 실제 페이지의 텍스트/이미지 순서·좌표·긴 키워드 범위, 메시지 영역·본문 높이 유지, 권한 선언, 휴대폰 입력 무응답 안내와 전체 회귀 테스트를 통과했습니다. 브라우저 미리보기도 갱신했습니다.

근거: [Even 권한 목록](https://github.com/even-realities/everything-evenhub/blob/main/plugins/everything-evenhub/skills/build-and-deploy/SKILL.md), [Apple 녹음 권한](https://developer.apple.com/documentation/avfaudio/avaudioapplication/requestrecordpermission(completionhandler:)).

## 2.3.0 — 1:1 비트맵 아이콘과 메뉴 입력 전환

현재 안경 패키지는 **2.3.0**입니다. 안경 앱 업데이트로 적용되며 게이트웨이 추가 재시작은 필요 없습니다.

- 상단의 원형 작동 기호를 안경/휴대폰 + 마이크 켜짐/꺼짐 4종 이미지로 교체하고 AI 호출어 왼쪽에도 별도 아이콘을 넣었습니다. 실제 편집 원본은 `assets/hud-icons`의 **24×24 PNG** 5종입니다. 원본 1픽셀을 안경 1픽셀로 표시하며 SVG 로딩이나 크기 보간을 하지 않습니다. 생성된 PNG는 안티앨리어싱 없는 1-bit 흑백/투명 비트맵이고, 편집 후 일반 RGBA PNG로 저장해도 지원합니다.
- PNG는 최초 로딩 시 packed Gray4로 변환·캐시합니다. 입력 소스·실제 마이크 상태가 바뀔 때만 아이콘을 갱신하고 AI 추론만으로 마이크를 켜짐으로 표시하지 않습니다. 이미지와 텍스트를 같은 큐에서 직렬 전송하며 페이지 재생성 후 이미지를 다시 보냅니다. 이미지 전송이 실패해도 본문을 계속 표시하고 입력/녹음 상태를 글자로 대체합니다.
- 기존 상단 27px 안에 아이콘을 배치하고 본문 높이를 유지했습니다. 우측 시간·배터리는 `16:14 | 75%`처럼 표시합니다.
- 안경 메뉴에 `입력 소스 전환`을 추가했습니다. 안경↔휴대폰을 전환하며 녹음 중이면 현재 음성을 마무리하여 전사·저장하고 마이크 종료 확인 후 새 소스로 녹음을 재개합니다. 대기 중에는 소스만 변경합니다. 빠른 중복 메뉴 입력은 직렬화하고 기존 마이크 종료가 불확실하면 새 소스를 열지 않습니다.

[아이콘 편집 안내](assets/hud-icons/README.md)와 `assets/hud-icons/preview.html`에 편집 방법과 배치 예시가 있습니다. PNG를 직접 고친 뒤 `npm run pack`으로 재패키징할 수 있습니다. `draw-bitmaps.mjs`는 명시적으로 실행할 때만 원본 PNG를 다시 그리며 일반 빌드에서는 실행하지 않습니다.

검증: 브라우저에서 5개 PNG의 실제 크기 로딩/Gray4 변환, 픽셀 데이터·캐시·레이아웃 범위, 마이크 상태 아이콘 선택, 페이지 재생성 후 이미지 재전송과 실패 시 텍스트 유지, 메뉴 전환 중 전사 저장·종료 후 재개·중복 입력 방지·대기 중 전환 및 전체 회귀 테스트를 통과했습니다. 실제 G2의 밝기·선명도와 Bluetooth 전송은 기기에서 확인해야 합니다.

## 2.2.7 — 안경·디바이스 오디오 입력 선택

현재 안경 패키지는 **2.2.7**입니다. 안경 앱 업데이트로 적용되며 게이트웨이 추가 재시작은 필요 없습니다.

- 설정의 `오디오 입력 소스`에서 `안경 · G2 마이크` 또는 `디바이스 · 휴대폰 마이크`를 선택합니다. SDK 0.0.16의 AudioInputSource.Glasses / Phone을 사용합니다. 디바이스는 Even 앱을 실행하는 휴대폰이며 Mac 서버의 마이크가 아닙니다. 기본값과 이전 설정은 안경입니다.

## 2.2.6 — 힌트의 주제 차단 완화와 정보 관점 다양화

현재 안경 패키지는 **2.2.6**입니다. 안경 앱 업데이트로 적용되며 게이트웨이 추가 재시작은 필요 없습니다.

- 같은 주제명을 3분 동안 차단하던 표시 규칙을 일반 표시 대기(기본 8초)로 줄였습니다. JEV에 전달하는 이미 표시한 발화 제외 범위도 최근 20초로 줄여 계속되는 대화의 새 세부 정보를 선별할 수 있게 했습니다. 동일·유사한 힌트 본문의 3분 반복 방지는 유지합니다.
- 생성 프롬프트에서 이전 주제 전체를 제외하라는 지시를 제거했습니다. 최근 6개·최대 1,200자의 실제 표시 내용(주제+사실)을 전달하고, 같은 주제에서도 사례·차이·시기·수치·원리·실용적인 의미·조건/예외 중 대화에 관련된 미제공 관점을 고르게 합니다. 내부 지식 즉시 생성, 조회 계획, 검색 근거 답변 모두 동일한 원칙을 사용합니다.
- LLM을 상시 호출하거나 목록을 기계적으로 순환하지 않습니다. 기존 EmbeddingGemma 2 + JEV 선별, 생성 최소 8초 간격, 표시 후 대기, 현재 주제 관련성 검사 및 사실 반복 검사를 유지합니다. 표시 이력은 최대 24개로 제한합니다.

검증: 같은 주제의 새 발화·다른 관점이 기본 대기 후 다시 생성 후보가 되는지, 기존 사실은 계속 반복 차단되는지, 옛 전사가 3분간 해당 주제를 막지 않는지, 각 생성 단계에 이전 표시 내용이 전달되는지와 기존 회귀 테스트를 통과했습니다. 실제 대화에서의 다양성과 유용성은 모델·전사·JEV 선별 품질에도 영향을 받습니다.

## 2.2.5 — 자율 정보 힌트와 명시적 AI 채팅 구분

현재 안경 패키지는 **2.2.5**입니다. 안경 앱 업데이트로 적용되며 게이트웨이 추가 재시작은 필요 없습니다.

- 힌트 계획·즉시 생성·검색 근거 기반 생성 모두 시스템 역할을 `자율 정보 제공`으로 명시합니다. 전사 속 질문·명령·검색 요청은 관찰 자료이며 사용자 지시가 아님을 분명히 했습니다. 내부 `question` 필드도 사용자 질문이 아닌 조사 항목으로 설명합니다. 질문에 응대하는 문구 대신 현재 토픽에서 대화에 아직 없는 배경·비교·시기·수치·근거를 객관적 메모로 제공합니다.
- 의문문이나 `검색해줘`를 인식하면 JEV를 건너뛰고 직접 답하던 경로를 제거했습니다. 호출어 없는 전사는 문장 형식과 관계없이 EmbeddingGemma 2 + JEV 선별을 거칩니다. 후보가 아니면 LLM을 호출하지 않고, 필요할 때만 내부 지식/검색/허용된 기억으로 힌트를 보충합니다.
- 호출어+질문, 호출어만 말한 뒤 이어지는 질문, 직접 입력한 질문은 기존의 문맥이 있는 AI 채팅으로 처리합니다. 명시적 질문은 힌트보다 우선하고 채팅의 긴 대기 예산을 사용합니다.

검증: 주변 의문문·검색 요청이 직접 AI 답변을 만들지 않는지, JEV 선별 후 자율 정보 메모 요청으로 전환되는지, 호출어 질문의 힌트 중단·문맥 채팅, 힌트 모델 상속 및 전체 회귀 테스트를 통과했습니다. 실제 모델마다 문체 준수 정도에는 차이가 있을 수 있습니다.

## 2.2.4 — 자동 인식 언어의 상단 표시 수정

인식 언어가 `Auto`이면 상단에 `AUTO→KO`처럼 선택 상태를 표시합니다. 이전에는 엔진에 전달하는 대체 언어 코드가 표시되어 자동 설정도 `EN→KO`로 보였습니다. 실제 엔진의 언어 결정·자동 준비 경로는 유지합니다. 안경 앱 업데이트만 필요합니다.

## 2.2.3 — 긴 추론·도구 실행의 AI 채팅 대기

현재 안경 패키지는 **2.2.3**입니다. 2.2.2의 엔진 자동 준비 기능을 포함하며 안경 앱 업데이트로 적용됩니다. 이 변경을 위한 게이트웨이 추가 재시작은 필요 없습니다.

- 호출어 질문·직접 입력한 AI 채팅에 적용되던 고정 45초 제한을 제거했습니다. 게이트웨이의 최대 5분 처리 예산과 전송 여유를 고려해 총 5분 30초, 서버에서 아무 데이터도 오지 않는 시간은 5분으로 제한합니다. 추론·도구·진행률·SSE 데이터 수신도 연결 활동으로 인정합니다. 자동 힌트 30초와 번역·주변 단발 응답 45초 제한은 유지합니다.
- 시간 초과와 연결 오류를 구분해 표시합니다. 이미 받은 답변이 있으면 안경 본문에 유지하고 휴대폰 출력에 중단 원인을 덧붙입니다. 실패·미완료 답변은 성공한 AI 채팅 문맥에 저장하지 않습니다. 중단된 요청을 자동 재전송하지 않아 도구가 중복 실행되는 것을 피합니다.
- 기존 호출어로 새 질문 대기·모드 변경 시 취소와 전사 지속 동작을 유지합니다. 모델 제공자나 게이트웨이 자체의 제한 시간은 별개이며 해당 모델 실사용에서 보고된 모든 연결 오류의 원인을 확정한 것은 아닙니다.

검증: 가상 시계로 45초 이후 채팅 지속, 추론 중 활동, 총/무응답 상한 및 타이머 정리를 확인했습니다. 실제 앱 요청 경로의 긴 대기 예산과 부분 답변 뒤 연결 오류 시 본문 유지, 서버 오류 원인 보존 및 기존 회귀 테스트를 통과했습니다. 특정 Qwen 모델의 실제 장시간 도구 실행을 이번 테스트에서 재현하지는 않았습니다.

## 2.2.2 — 번역·STT 조건 변경 시 자동 준비

현재 안경 패키지는 **2.2.2**입니다. 이 변경은 안경 앱 업데이트로 적용되며 게이트웨이 추가 재시작은 필요 없습니다.

- Chrome·Apple 번역 엔진 선택, 번역 방향 변경 시 자동으로 해당 언어팩을 준비합니다. STT 엔진·인식 언어·AI/번역 모드가 바뀌면 실제 사용할 인식 언어를 자동 준비합니다. Whisper 선택도 상태 확인과 워밍업을 수행합니다. 인식 언어가 자동이면 목표 언어에 따라 정해지는 실제 인식 언어로 준비합니다.
- 로그인·인증된 설정 복원·서버/계정 설정 저장 후에도 현재 엔진을 자동 준비합니다. 녹음 시작 시 STT 상태를 다시 확인하고, 번역 직전에는 진행 중인 언어 준비를 기다립니다. 서버 재시작이나 언어팩 삭제로 번역이 실패하면 한 번 재준비·재시도한 뒤 기존 LLM 번역 대체 경로로 넘어갑니다.
- 같은 조건의 준비는 공유합니다. 역할별 준비는 한 번에 하나만 진행하고 설정을 빠르게 바꾸면 대기 작업은 최신 조건 하나만 유지합니다. 이전 조건의 완료/오류로 현재 상태를 덮지 않으며, 엔진 선택기는 준비 중에도 변경할 수 있습니다. 준비 버튼은 수동 재시도용으로 유지합니다.
- 최초 다운로드와 Apple 시스템의 언어팩 설치 확인 창은 필요할 수 있습니다. 녹음 준비 중 모드·언어를 바꾸면 해당 녹음 시작을 취소하여 이전 조건으로 마이크가 열리지 않도록 합니다. 마이크를 끄더라도 공유 중인 언어팩 준비는 계속됩니다.

검증: 버튼 클릭 없이 Chrome/Apple 번역·STT 선택, 인식/목표 언어 변경, 자동 인식 언어의 재계산, AI 모드 한국어 전환, 설정 복원 후 자동 준비를 앱 경로로 확인했습니다. 중복 준비 공유·최신 조건 우선·이전 상태 무효화·실패 재시도·녹음 취소와 기존 회귀 테스트를 통과했습니다.

## 2.2.1 — 실시간 번역 안정화와 전사 대기 분리

현재 안경 패키지는 **2.2.1**입니다. 안경 앱을 업데이트하고, Apple STT를 사용한다면 수정된 Mac 게이트웨이 앱을 완전히 종료·재실행하세요.

- Apple·Chrome 로컬 번역은 STT가 확정한 접두사 중 완결된 문장을 따로 번역·재사용합니다. 마지막 미완성 문장만 다시 번역합니다. 구두점이 없거나 확정 접두사가 원문과 일치하지 않으면 문장 전체를 유지해 문맥을 자르지 않습니다. 최종 STT가 원문 자체를 교정한 문장은 다시 번역할 수 있습니다.
- 문장 번역 캐시는 현재 구간/언어/엔진별 최근 32개·원문+번역 8,000자로 제한합니다. 반복 사용 중인 확정 문장은 마지막 부분이 여러 번 바뀌어도 우선 유지합니다. 기존 표시 기록 30줄 제한은 유지합니다.
- Apple·Whisper 전사의 최신 프리뷰는 최종 전사·저장 대기열과 별도로 진행합니다. 엔진 사용 중(429)이면 최신 스냅샷 하나만 보관하고 300ms 뒤 재시도합니다. 음성 엔진 자체의 연산은 여전히 직렬이며 무제한 병렬 추론을 하지 않습니다. Chrome STT는 하나의 연속 브라우저 음성 스트림 순서를 보존하기 위해 기존 전사 순서를 유지합니다.
- Apple 보조 엔진은 구간 교체로 중지한 미완료 세션을 폐기합니다. 나중에 대기 음성을 처리하거나 실시간 구간으로 돌아오면 전체 PCM 스냅샷으로 복원하여 예전의 일부 전사만 반환하지 않도록 했습니다. 완료된 세션의 중복 요청 처리는 유지합니다.
- 새 발화·확정 번역은 오래된 번역 요청의 타임아웃을 기다리지 않고 취소합니다. 뒤늦게 저장된 이전 구간은 최신 번역 화면을 되돌리지 않으며, 전사 기록은 계속 순서대로 저장합니다. 녹음을 재시작하면 새 세션의 시간 기준을 사용합니다.

검증: 저장 응답과 대기 음성을 보류한 상태에서 Apple 프리뷰·번역이 갱신되고, 저장 완료 후에도 최신 자막이 유지되는 앱 경로를 확인했습니다. 확정 문장 재사용·최종 원문 교정·50회 말미 수정·캐시 상한·취소/오래된 결과 차단 및 기존 앱 회귀 테스트를 통과했습니다. 실제 Apple 엔진에서 구간 교차 후 전체 음성 복원, 최종 전사·SQLite 저장·중복 방지·번역 테스트를 통과했습니다. 실제 G2 장시간 대화에서 지연이 완전히 사라지는지는 별도 실측이 필요합니다.

## 2.2.0 — 역할별 LLM 모델 할당

현재 안경 패키지는 **2.2.0**입니다. 안경 앱 업데이트로 적용되며 이 기능을 위한 게이트웨이 재시작은 필요 없습니다.

- 설정의 `역할별 LLM 모델 할당`에서 기본 모델과 AI 채팅·AI 힌트·번역·번역 답변 모델을 고릅니다. 각 역할 목록의 첫 항목은 `기본 모델 사용`이며 현재 기본 모델 이름을 함께 표시합니다. 기본 모델을 변경해도 명시적으로 선택한 역할 모델은 유지합니다.
- 호출어 질문과 직접 입력한 AI 채팅은 AI 채팅 모델을, 평소 힌트의 계획·정보 생성 및 주변 질문 답변은 AI 힌트 모델을 사용합니다. EmbeddingGemma 2 + JEV의 선별 경로는 유지합니다.
- LLM 번역과 번역 답변에 서로 다른 모델을 선택하면 번역문을 먼저 표시하고 답변 모델이 긍정·부정 예시를 생성합니다. 두 역할의 실제 모델이 같으면 기존처럼 한 번의 요청으로 처리합니다. Apple·Chrome 번역은 해당 번역 엔진을 사용하고 LLM 예상 답변만 번역 답변 모델에 요청합니다.
- 선택은 앱 설정과 함께 저장·복원합니다. 서버 목록에서 사라진 역할 모델도 선택값을 보존하고 `현재 목록에 없음`으로 표시하므로 사용 가능한 모델로 변경할 수 있습니다. AI 채팅 문맥은 실제 AI 채팅 모델이 바뀌면 새로 시작합니다.

검증: 역할별 실제 요청 모델, 힌트 계획/답변, 번역/답변 분리와 기존 표시 유지, Apple 번역의 답변 모델, 기본 모델 상속·명시적 선택 유지·재실행 복원 및 기존 앱 회귀 테스트를 통과했습니다.

실시간 번역의 교정과 지연에 대한 별도 검토는 [REALTIME_TRANSLATION_REVIEW.md](REALTIME_TRANSLATION_REVIEW.md)에 기록했습니다. 해당 검토에 따른 번역 처리 구조 변경은 포함하지 않습니다.

## 2.1.0 — macOS Apple 로컬 STT·번역 옵션

현재 안경 패키지는 **2.1.0**입니다. Mac 게이트웨이 앱을 완전히 종료한 뒤 새 앱으로 재실행하고, 안경 앱도 업데이트하세요.

- macOS 26 이상에서 `Apple 로컬 STT`와 `Apple 로컬 번역`을 각각 선택할 수 있습니다. 서버에서 실제 기기 지원을 조회해 선택을 활성화합니다. SpeechTranscriber 미지원 기기에서는 STT 옵션을 비활성화합니다. 다른 OS 또는 보조 엔진이 없는 구버전 게이트웨이에서는 Apple 옵션을 사용할 수 없습니다.
- STT는 SpeechAnalyzer/SpeechTranscriber로 G2의 PCM을 이어서 분석합니다. 임시 결과는 교정하고 최종 결과만 저장·호출어·AI 채팅으로 보냅니다. 최종 음성만 업로드해도 처리하며, 전체 스냅샷 재전송 시 새 PCM만 공급합니다. 같은 세션의 요청은 네이티브 쪽에서도 직렬화해 취소된 프리뷰와 최종 업로드가 겹쳐 중복 입력되지 않도록 했습니다.
- STT 엔진 준비는 녹음 시작 시 자동으로 수행합니다. 최초에는 Apple 모델 준비/다운로드가 필요할 수 있습니다. 중지·다른 언어 준비·모델 예약 한도를 처리하며 Mac 마이크를 별도로 녹음하지 않습니다. 선택 엔진 실패 시 Whisper 사용 체크를 켠 경우에만 최종 인식 또는 준비 실패를 Whisper로 대체합니다.
- 번역 엔진은 LLM / Chrome 로컬 / Apple 로컬 중 선택합니다. 기존 Chrome 사용 여부 설정은 재실행 시에도 원래 선택으로 이전합니다. Apple은 `번역 엔진 준비` 버튼으로 언어 방향을 최초 준비하세요. 필요하면 Mac에 Apple 공식 언어팩 준비 창이 열립니다. 이후 앱/보조 엔진 재시작 후에도 설치된 언어를 재사용합니다.
- Apple 번역도 기존 중간 인식 갱신·최신 대기열·30줄 표시 기록·긍정/부정 답변 경로를 사용합니다. 번역 오류가 나면 마지막 박스 내용은 유지하고 기존 LLM 번역 경로로 전환합니다. STT·번역 처리는 Apple 온디바이스 API를 사용하며, 힌트/채팅/예상 답변 LLM의 연결 설정은 별개입니다.
- 게이트웨이 앱 안에 Swift 보조 엔진을 포함합니다. 사용자는 Xcode를 설치할 필요가 없습니다. 개발자는 Xcode 26+에서 `scripts/build-apple-runtime.sh`로 보조 엔진을 빌드합니다. Wails macOS 빌드의 postBuildHooks에도 연결했으며 arm64/x86_64 공용 바이너리를 생성합니다. 구형 SDK에서는 보조 엔진만 생략합니다.

검증: 실제 설치된 Apple 엔진으로 한국어 합성 음성의 임시/최종 전사, 프리뷰 없는 최종 업로드, 호출어 매칭, SQLite 중복 저장 방지, 프리뷰의 저장/호출 부작용 없음, 한→영 번역, 보조 엔진 재시작 후 무준비 번역을 확인했습니다. 앱 테스트는 Apple 엔진 선택/준비/API 전달·실시간 번역 교체와 기존 설정 이전을 포함합니다. 기존 Go 코어·채팅 및 앱 회귀 테스트도 통과했습니다. 실제 G2 음성과의 품질·지연 비교는 별도 확인이 필요합니다.

- 프롬프트/모델 로딩/검색 상태를 답변 박스에 표시하지 않고 상단에서 갱신합니다. 새 답변 본문이 오기 전까지 마지막 답변을 유지합니다. 진행률은 실제 서버 이벤트 값만 표시합니다.

검증: 별도 Chrome 프로필에서 한국어 합성 음성의 누적 중간/최종 문장 인식과 저장을 확인했습니다. 앱 테스트는 짧은 쉼을 사이에 둔 문장 전체의 번역 API 전달, 가설 수정/지연 결과/문맥 경계, 세 모드 공통 헤더와 본문 보존, 기존 음성/번역/힌트 회귀 테스트를 포함합니다. 실제 안경 환경의 재확인은 필요합니다.

## 1.7.1 — 마지막 예상 답변 유지

검증: 임시 번역 중 하단 내용 유지, 스트리밍/부분/빈 응답 유지, 완성된 쌍의 동시 교체 및 기존 앱 회귀 테스트를 통과했습니다.

## 1.7.0 — 중간 인식의 실시간 번역과 확정 교체

현재 패키지는 **1.7.0**입니다. 새 확정/임시 전사 필드를 사용하려면 Mac 게이트웨이도 업데이트·재시작하세요. 구버전 전사 응답은 전체 text를 임시 결과로 처리하는 호환 경로가 있습니다.

- 이전에는 Chrome 중간 인식을 받더라도 번역 박스에 보내는 경로는 최종 전사 이후에만 실행됐습니다. 이제 중간 전사도 Chrome Translator로 보내 문장이 끝나기 전에 번역문을 갱신하고, 마지막 확정 전사로 같은 박스를 교체합니다. 이전 문장을 중복 추가하지 않습니다.
- 중간 번역은 진행 중 1개+최신 대기 1개만 유지하며 완료 후 최소 500ms 간격으로 처리합니다. 새 발화의 첫 번역과 최종 교체는 이 대기를 건너뜁니다. 같은 중간 문자열의 성공 번역은 다시 요청하지 않으며 busy/실패는 다음 프리뷰에서 재시도할 수 있습니다. 실제 지연은 인식·네트워크·번역 시간에 따라 달라집니다.
- 새 중간 결과가 들어왔다는 이유만으로 진행 중인 유효한 중간 번역을 계속 폐기하지 않습니다. 같은 발화 안에서는 순서대로 표시하고, 최종 결과가 요청됐거나 발화/모드가 달라지면 이전 결과를 무시합니다. 확정 결과 뒤 늦은 임시 결과가 덮어쓰지 않습니다.
- 중간 번역으로는 LLM 답변 예시 생성·SQLite 저장·AI 호출어 판별을 하지 않습니다. 확정 결과만 기존 저장·AI 경로에 연결합니다. 중간 Chrome 번역에 실패해도 LLM 번역을 반복 호출하지 않고 현재 박스를 유지합니다. 최종 Chrome 번역 실패는 기존 LLM 경로로 복귀합니다.
- Chrome의 확정 prefix와 임시 suffix를 `stableText`/`draftText`로 구분해 전달합니다. 화면에서는 최신 가설로 갱신하며 최종 전사로 교체합니다. 이 구분은 DB 저장 완료 여부와 별개입니다. Whisper는 기존 LocalAgreement를 유지합니다.
- 길어지는 임시 번역은 마지막 줄을 따라 표시하고, 확정 문장은 기존 읽기/스크롤 동작을 사용합니다. 번역 박스는 번역문만 유지하며 진행 상태는 고정 상단 줄에 남깁니다. 모드 전환으로 중간 번역 요청을 취소해도 같은 Chrome의 STT 세션 전체를 종료하지 않도록 했습니다.

검증: 앱에서 최종 STT/LLM 호출 전에 중간 번역 표시, 중간 교정·최종 교체·중간 LLM 미호출·늦은 결과/모드 취소 방어·요청 간격 테스트. 실제 합성 한국어에서 온라인 Chrome STT의 30개 변경 가설을 같은 Chrome의 로컬 Translator로 번역하고 최종 결과를 교체했으며, 최종 저장/중복 방지/호출어 테스트도 통과했습니다. 이 테스트는 모든 번역의 의미 정확도나 실제 G2 지연을 보장하지 않습니다.

## 1.6.1 — Chrome 프로필 잠금 복구·고정 통번역 상태줄

현재 패키지는 **1.6.1**입니다. 프로필 잠금 개선은 Mac 게이트웨이 업데이트·재시작도 필요합니다.

- 번역 상단은 `[번역] EN→KO | 작동중 | 프롬프트 처리 32%`처럼 언어 방향·작동/대기·진행 단계의 세 필드를 유지합니다. 실제 인식/번역 언어 코드를 사용하며, 단계 변경이나 점 애니메이션으로 앞부분 문구를 교체하지 않습니다. 퍼센트는 서버가 제공할 때만 표시합니다. 시계·안경 배터리 영역은 유지합니다.
- 기존 34단위 문자 수 제한 때문에 퍼센트가 잘리던 경로를 실제 396px 텍스트 폭 제한으로 바꿨습니다. 긴 호출어도 같은 폭 안에서 말줄임합니다. 진행률은 번역 박스에 표시하지 않습니다.
- Chrome 전용 프로필에 OS 파일 잠금을 추가해 게이트웨이 중복 사용을 먼저 차단합니다. 잠금 파일은 삭제하지 않고 같은 inode를 유지하며 핸들 종료/프로세스 종료 시 OS가 소유권을 해제합니다.
- macOS/Linux에서는 기존 Chrome의 SingletonLock을 읽고 실제 프로세스의 부모·실행 파일·NUL 구분 인자를 확인합니다. 부모가 이미 종료되어 init에 인계된, 정확히 같은 전용 프로필의 headless Chrome만 정상 종료를 요청합니다. 일반 Chrome, 다른 프로필, 살아 있는 게이트웨이의 Chrome은 종료하지 않습니다. Chromium의 SingletonLock 파일은 직접 삭제하지 않습니다. 확인할 수 없는 프로세스는 복구를 시도하지 않고 다른 게이트웨이 종료 안내를 표시합니다.
- 원시 Chromium 프로세스 오류 덤프를 그대로 화면에 노출하지 않고 중복 실행·시작 실패 안내를 짧게 표시합니다. 언어팩과 기존 준비 이력은 보존합니다.

검증: 고정 헤더·실제 32% 이벤트·번역문 유지·396px 폭 제한, 프로필 잠금 획득/중복 거부/해제, 실제 OS 인자 검증·다른 프로필 및 살아 있는 부모 보호 테스트. 실제 Chrome 두 worker에서 중복 실행 차단과 정상 종료 후 프로필 재사용을 검증했습니다.

## 1.6.0 — Chrome 온라인 STT·번역문 유지

현재 패키지는 **1.6.0**입니다. Mac 게이트웨이도 새 실행 파일로 업데이트·재시작해야 합니다.

- 설정의 음성 인식 엔진에서 `Whisper` 또는 `Chrome 온라인 STT · Google로 음성 전송`을 선택합니다. 기존 사용자의 기본값은 Whisper입니다. Chrome 온라인을 선택한 경우에만 해당 엔진으로 음성을 전달하며 음성이 Google로 전송된다는 점을 UI에 표시합니다. 정식 Mac Chrome을 사용하고 Mac 마이크를 따로 녹음하지 않습니다.

- 연속 모드는 Chrome일 때 약 250ms 단위로 프리뷰를 요청하고 중간 결과를 그대로 갱신합니다. Whisper의 기존 LocalAgreement 경로와 1초 주기는 유지합니다. 수동 녹음도 Chrome 중간 자막을 요청합니다. 최종 전사만 기존 SQLite 저장·호출어 판별·번역/AI 경로로 전달합니다.
- Chrome 모드는 Whisper 설치/예열에 의존하지 않습니다. `Chrome 오류 시 Whisper 사용`이 켜져 있으면 준비 실패 또는 최종 인식 오류 때 사용 가능한 Whisper로 전환하고 상태에 표시합니다. busy 프리뷰는 건너뛰며 자동으로 로컬 선택을 온라인으로 바꾸는 기능은 없습니다.
- 녹음 중 엔진 선택을 잠그고, 폐기한 발화의 브라우저 세션을 종료합니다. Chrome 음성 세션은 계정·녹음 세션·발화 ID로 구분하고 세션 캐시·유휴 시간을 제한합니다. 중간 결과는 저장·트리거 평가하지 않습니다.
- Chrome의 로컬 STT는 오디오 트랙 입력에서 브라우저가 중단되는 현상을 실제로 확인하여 이번 UI에서 제외했습니다. `chrome-local` 요청도 정상 지원 엔진으로 취급하지 않습니다. 현재 제공하는 Chrome 모드는 검증된 온라인 경로입니다.
- Chrome이 번역할 때 박스에는 이전/현재 번역문을 유지합니다. ‘생각 중’, ‘프롬프트 처리 중’ 등 처리 상태는 기존 실시간 통번역 상태줄에 표시하며 번역문 박스를 대체하지 않습니다. 처음 번역이 오기 전에는 박스를 비워 둡니다.

검증: 개인정보가 없는 약 12초 합성 한국어를 온라인 엔진에 보내 첫 중간 자막 약 0.6초부터 점진적으로 갱신되는 것을 확인했습니다(이 테스트는 약간 빠르게 PCM을 공급했으며 실제 장치·네트워크 지연을 보장하지 않습니다). 최종 인식·SQLite 저장·중복 최종 요청의 한 번 저장·호출어 판별·프리뷰 미저장, 엔진별 예열 분기, 번역 박스 내 상태 문구 제외 및 기존 회귀 테스트를 확인했습니다. 실제 G2에서의 장시간 연결·네트워크 변화는 추가 관찰이 필요합니다.

## 1.5.0 — Whisper 전사 + Chrome 로컬 번역

현재 패키지는 **1.5.0**입니다. Mac 게이트웨이 실행 파일도 새 API가 포함된 버전으로 업데이트·재시작해야 합니다.

- 음성은 계속 기존 Whisper가 전사합니다. 번역 모드에서 `Chrome 로컬 번역 사용`을 켜면 확정 전사문만 Mac의 정식 Google Chrome Translator API로 번역합니다. iPhone WebView나 검색용 Headless Shell의 기능을 사용하지 않습니다.
- 인식·번역 언어를 선택하고 `Chrome 번역 준비`를 누르면 전용 영속 프로필에 해당 언어 쌍의 모델을 준비합니다. 최초 다운로드에는 시간이 걸릴 수 있습니다. 준비 이력을 별도로 저장해 worker 재시작 후 복원합니다. 일반 Chrome 프로필·로그인·탭은 사용하지 않습니다. 서버 종료 시 전용 Chrome도 종료합니다.
- Chrome 번역문을 먼저 박스에 표시한 뒤 LLM은 긍정·부정 답변 예시만 생성합니다. 이 요청에는 자동 기억·웹검색 도구를 붙이지 않습니다. LLM이 translation 필드를 보내도 Chrome 번역문을 덮지 않습니다. 답변 생성에 실패해도 완료된 번역문을 유지합니다.
- 연속 발화의 Chrome 번역 처리는 LLM 대기열과 분리합니다. 진행 중 한 개와 최신 대기 한 개만 유지하고 이전 발화의 답변 생성은 새 발화 때 취소합니다. revision이 지난 Chrome/LLM 결과는 최신 번역을 덮지 않습니다. 원문 전사 SQLite 저장은 기존대로 유지합니다.
- 정식 Chrome 미설치·모델 미준비·미지원 언어·시간 초과 등에는 기존 LLM 번역으로 복귀하며 휴대폰에 이유를 표시합니다. Chrome 브라우저 번역 요청은 8초, 서버 작업은 12초 제한입니다. 번역 준비 요청은 최대 180초입니다. 준비 작업 중 번역 요청은 무제한 쌓지 않고 busy를 반환합니다.
- `자동` 인식 언어의 경우 기존 Whisper에 실제 전달한 언어와 같은 코드를 사용합니다(목표 한국어면 기본 영어, 그 외 기본 한국어). 다국어 음성 자동 판별을 새로 추가한 것이 아니므로 정확한 인식 언어를 선택하는 것을 권합니다. 언어 쌍을 바꾸면 준비 버튼으로 해당 쌍을 준비할 수 있습니다.

검증: 실제 정식 Chrome에서 한국어→영어(`커피 드시겠어요?` → `Would you like some coffee?`), 영어→한국어 번역과 worker 재시작 후 복원을 확인했습니다. 별도 프로필에 양방향 준비를 마쳤습니다. HTTP 입력·대기열·CORS 검증, Chrome 준비 실패 시 기존 경로, LLM 지연 중 다음 발화 번역, LLM의 번역 덮어쓰기 방지 및 오류 시 번역 유지 회귀 테스트를 통과했습니다. 브라우저 상주 RAM·장시간 연속 번역 지연은 별도 실측이 필요합니다. Chrome STT로의 전환은 아직 하지 않았습니다.

## 1.4.12 — 웹검색 우선·전사 속 문장 선별·설정 겹침 수정

현재 패키지는 **1.4.12**입니다. 새 JEV 선별은 게이트웨이 실행 파일 업데이트·재시작도 필요합니다.

- AI 설정에 `정보 힌트는 웹검색 우선`을 추가하고 기본으로 켭니다. JEV가 선별한 배경·개념·사실 확인 후보는 검색 근거 조회 후 한 번의 생성 요청으로 답합니다. LLM이 검색 필요성을 다시 판단하는 계획 단계를 생략합니다. 개인 기억·발언 제안은 이 강제 웹 경로에 넣지 않습니다. 옵션을 끄면 기존 내부 지식 우선 경로를 사용합니다.
- 실제 검색 도구·계정 설정을 존중합니다. 서버의 검색 근거 조회가 실패(424)하면 한 번의 내부 지식 생성으로 전환할 수 있고, 그 경우 휴대폰 상태에 웹검색 사용 불가/내부 지식임을 명시합니다. 근거 없이 웹검색 결과로 표시하지 않습니다. 불확실하거나 생략된 결과는 기존 힌트를 유지합니다.
- JEV 기준에 제품·모델명·회사·기관·약어·정책·장소 등 일상 대화 속 공개 지식 명칭을 포함했습니다. 여러 문장에서는 최근 최대 4개 실질 발화를 JEV가 선택하고, 선택 문장이 공개 정보 후보인지 별도 이진 분류로 확인합니다. 단순히 문장 유사도가 높다는 이유로 식사·일정 대화를 검색하지 않습니다. 반환되는 focus는 원문 문장이며 클라이언트도 원문 포함 여부를 검사합니다.
- JEV 선별 전체에 7초 예산을 적용하고 생성 LLM을 상시 판단에 사용하지 않습니다. 임베딩이 일시적으로 사용 중이면 새 발화가 없어도 최신 후보를 한 번 재판별합니다. 기존 생성 간격·성공 표시 후 쿨다운·최신 대기 하나 정책을 유지합니다.
- 번역 설정 체크박스와 안내문을 언어 선택 격자의 전폭 행으로 분리하고 체크박스 폭·정렬을 고정했습니다. 390px 너비 렌더링으로 겹침을 확인했습니다. 안내문도 Whisper STT 이전 화자 메타데이터 필터임을 명확히 했습니다.

검증: 앱 회귀 테스트(검색 우선 한 번 생성, 검색 실패 내부 지식 전환 포함), 서버 검색 권한·근거 주입·프롬프트 격리 테스트, 실제 로컬 JEV의 EBITDA/맥북 에어 M4 문장 선별 및 식사·일정 제외 3개 예문. 소수 예문 결과이며 일반 정확도나 지연 개선 수치를 보장하지 않습니다. 실제 장시간 대화에서의 누락·불필요한 개입은 추가 관찰이 필요합니다.

## 1.4.11 — 번역 모드에서 내 목소리 제외

현재 패키지는 **1.4.11**입니다. 1.4.6 게이트웨이가 실행 중이면 안경 앱만 업데이트하면 됩니다.

- 번역 언어 설정에 `번역 중 내 목소리 제외` 옵션을 추가했습니다. 기본값은 켜짐이며 변경 즉시 저장합니다.
- Even SDK `speakerRole`이 `self`인 PCM 프레임을 무음으로 치환해 내 발화가 STT·번역을 시작하지 않게 합니다. 오디오 시간과 침묵 경계를 유지하므로 상대방의 발화 종료 감지는 계속됩니다. 기존 전사 대상이 ‘내 목소리 우선’이어도 번역 모드에서는 이 제외 옵션이 우선합니다.
- `other`와 `unknown`은 통과시킵니다. SDK 화자 분류는 Even 앱의 알고리즘 결과이며 신원 보장이 아닙니다. 구형 호스트·분류 미지원 환경·동시 발화에서는 내 음성을 완전히 배제하지 못할 수 있습니다. 별도 화자 모델이나 LLM 호출은 추가하지 않습니다.
- 옵션을 끄면 기존 전사 대상 설정을 사용합니다. AI·전사 모드에는 기존 동작을 유지합니다.

검증: self 프레임의 번역 미시작, other/unknown 통과, 타 모드의 전사 대상 유지, PCM 길이·원본 보존 및 기존 회귀 테스트. 실제 기기의 화자 판별 정확도는 업데이트 후 확인이 필요합니다.

## 1.4.10 — 번역 예상 답변을 각각 두 줄로 표시

현재 패키지는 **1.4.10**입니다. 1.4.6 게이트웨이가 실행 중이면 안경 앱만 업데이트하면 됩니다.

- 번역 모드 하단은 긍정·부정 각각 두 줄, 총 네 줄입니다. 첫 줄은 `긍정: 목표 언어 답변`, 둘째 줄은 들여쓴 인식 언어의 뜻이며 부정도 같은 순서입니다. 한국어 → 영어 설정은 영어 답변 뒤 한국어 뜻을 보여줍니다.
- 답변 생성 지침에 언어 순서를 명시하고 JSON 문자열의 줄바꿈으로 두 언어를 분리합니다. 기존 ` — ` 구분 출력도 두 줄로 표시합니다. 긴 문장은 각 행의 실제 픽셀 폭에 맞춰 말줄임하여 네 줄을 넘기지 않게 합니다.
- 네 줄이 실제 안경에서도 보이도록 번역 모드에서만 박스 높이를 141px(내부 5줄), 하단을 y=168·높이 120px(4줄)로 변경합니다. 다른 모드에서는 기존 168px·6줄 박스와 3줄 전사 영역을 사용합니다. 모드 전환 시 SDK 화면 재구성을 기존 텍스트 갱신과 직렬 처리하며 메뉴를 유지합니다.
- 휴대폰 미리보기의 예상 답변 영역도 네 줄 높이로 늘렸습니다.

검증: 양언어 순서·두 줄 분리·들여쓰기·네 행의 픽셀 폭, 스트리밍 JSON, 번역 모드의 네 줄 공간·영역 경계·메뉴 유지 및 기존 회귀 테스트를 통과했습니다. 실제 안경에서의 표시 결과는 업데이트 후 확인이 필요합니다.

## 1.4.9 — JEV 선별 후 한 번의 힌트 생성·번역 역할 분리

현재 패키지는 **1.4.9**입니다. 1.4.6 게이트웨이가 실행 중이면 안경 앱만 업데이트하면 됩니다.

- 지속적인 후보 판별은 기존 로컬 EmbeddingGemma 2 + JEV가 담당합니다. 일반 발화마다 생성 LLM을 호출하지 않습니다. 후보를 통과한 개념·인물·응답 제안은 한 번의 LLM 요청으로 결과를 생성하며, 웹·기억 근거가 필요할 때만 조회 후 두 번째 생성 요청을 사용합니다. 이전 계획 형식으로 응답하는 모델은 기존 경로로 처리합니다.
- 자동 생성 시작 간 최소 간격은 8초, 성공 표시 후 쿨다운은 15초입니다. 실패·생략은 표시 성공으로 기록하지 않으며 짧은 4초 재시도 제한과 별도 생성 간격을 적용합니다. 진행 중 하나와 최신 대기 하나만 유지하고 전사 처리는 독립적으로 계속됩니다.
- 제안형 후보는 실제 말할 답변·확인 질문을, 개념·인물 후보는 새로운 배경 정보를 요청합니다. 최근 표시한 힌트 4개를 현재 세션의 참고로 전달하고 내용 반복을 억제합니다. 새로운 장기 메모리나 별도 LLM 요약 루프를 추가하지 않습니다.
- 새 자동 힌트를 생성할 때 기존 힌트를 비우거나 추론 상태로 교체하지 않습니다. 생략·오류 때도 기존 본문을 유지하고 휴대폰 상태에만 결과를 표시합니다. 생성 제한은 30초, 후보 표시 유효 기한은 45초(응답 제안 20초)로 줄였습니다.
- 표시 직전 새 발화와 주제 명칭의 연결을 보수적으로 재확인합니다. 여러 새 발화가 있고 12초 이상 지났는데 주제 표현이 연결되지 않으면 오래된 후보를 버립니다. 이는 어휘 기반 방어이며 의미적 주제 판별·정확한 해결 여부 추적을 보장하지 않습니다.
- 자동 힌트의 140자 단순 절단을 없애고 실제 570px·6줄 안에 들어가는 완결된 문장을 표시합니다. 첫 문장도 너무 길면 잘라 보여주지 않고 생략합니다. 직접 질문의 상세 답변·스크롤은 유지합니다.
- 번역 출력은 `translation`, `positive`, `negative`의 세 JSON 문자열로 분리합니다. 박스는 들은 말의 번역문이고, 하단 두 항목은 그 말에 사용자가 대답할 긍정·부정 예시입니다. 질문 번역을 예상 답변에 반복하지 않도록 지침·예시를 보강했습니다. 이미 목표 언어인 발화는 같은 언어로 유지합니다. 스트리밍 JSON을 필드별로 읽어 번역문부터 갱신하고 기존 라벨 형식도 호환합니다.

검증: 단일 LLM 호출 경로, 쿨다운·실패 재시도·생성 간격, 구식 후보 폐기, 문장 단위 6줄 제한, 번역 스트리밍 필드 분리와 기존 앱 회귀 테스트. 실제 로컬 모델에서도 번역/긍정·부정 답변 분리와 응답 제안 생성을 확인했습니다. 기기 환경에서의 지연·장기 대화 유용성은 추가 실측이 필요합니다. 사전 자료 선택과 종료 후 요약은 이번 패키지에 추가하지 않았습니다.

## 1.4.8 — 번역문과 두 가지 예상 답변 분리

현재 패키지는 **1.4.8**입니다. 1.4.6 게이트웨이가 실행 중이면 안경 앱만 업데이트하면 됩니다.

- 번역 모드의 답변 박스에는 번역문만 표시합니다. 번역문이 길면 기존 스크롤을 사용합니다.
- 하단에는 긍정·부정 예상 답변 두 개만 표시하고 중립 답변과 원문 전사는 표시하지 않습니다. 전사 기록 저장은 유지합니다.

검증: 기존 앱 회귀 테스트, 스트리밍 부분 라벨·기존 중립 답변 제외·긴 예상 답변의 픽셀 폭 제한 테스트를 통과했습니다.

## 1.4.7 — 공식 SDK 캔버스 안에서 세로 여백 축소

현재 패키지는 **1.4.7**입니다. 1.4.6 게이트웨이가 실행 중이면 안경 앱 업데이트만 필요합니다.

- [공식 제품 사양](https://support.evenrealities.com/hc/en-us/articles/13499229138959-Specifications)은 해상도를 **640×350**으로 표기하지만, [공식 Even Hub 개발 문서](https://github.com/even-realities/everything-evenhub/blob/main/plugins/everything-evenhub/skills/glasses-ui/SKILL.md)는 앱 캔버스를 **576×288**로 명시합니다. 이 앱은 확인된 SDK 영역을 사용하며 640×350 좌표 지원은 확인하지 않았습니다.
- 상태 줄을 y=0, 높이 27px로 줄이고 헤더의 패딩을 명시적으로 0으로 했습니다. 답변 박스는 y=27, 높이 168px, 패딩 2px·테두리 1px입니다. 내부 높이 162px에 기본 27px 텍스트를 **6줄** 표시합니다. 기존 5줄보다 한 줄 더 표시합니다.
- 전사는 y=195, 높이 93px로 **3줄을 유지**합니다. 답변 박스와 전사 사이의 8px 간격을 제거하고 전사 컨테이너는 y=288까지 사용합니다. 휴대폰 미리보기의 박스 여백도 줄였습니다.
- SDK가 허용한 캔버스 안의 낭비를 줄인 수정입니다. 제품 패널 전체 영역을 SDK 앱에 추가로 개방하는 수정은 아닙니다. 기기 실측 없이 타 앱과 동일한 물리 표시 범위를 보장하지 않습니다.

검증: 영역 중첩·경계 초과 없이 바닥까지 배치되는지, 패딩·테두리를 제외한 답변 내부에 6줄이 들어가는지와 기존 앱 회귀 테스트를 확인했습니다.

## 1.4.6 — 안경 전용 프롬프트 조립과 문맥 격리

현재 패키지는 **1.4.6**입니다. Mac 게이트웨이를 완전히 종료·재실행하고 안경 앱도 업데이트해야 합니다.

## 1.4.1 — AI 모드는 최신 대화 우선, 누적 문맥으로 힌트 판별

현재 패키지는 **1.4.1**입니다. 게이트웨이를 완전히 종료·재실행하고 안경 앱도 업데이트해야 합니다.

- **AI 모드에서는 음성 처리 실패로 녹음을 정지하지 않습니다.** 실패·시간 초과 구간은 버리고 최신 음성을 계속 처리합니다. 재시도하지 않으며 진행 중인 1개와 최신 대기 1개만 유지합니다. 20초 이상 오래된 대기 구간도 생략합니다. 생략된 음성은 복원되지 않고 해당 구간의 전사 기록이 빠질 수 있습니다. 이 동작은 모든 발화 응답을 선택한 AI 모드에도 적용됩니다. 전사·번역 모드의 보관·재시도 정책은 유지합니다.
- AI 최종 전사는 `realtime: true`로 요청해 서버 엔진 사용 중이면 내부에 요청을 쌓지 않고 429로 응답합니다. 클라이언트는 12초 제한 후 해당 구간을 생략하고 다음 음성을 처리합니다. 이미 시작된 추론 자체를 강제 종료하는 기능은 아닙니다.
- 힌트는 최근 **20초 내 최대 6개 발화**를 묶어 판별합니다. 처음에는 최대 1.2초 수집하고, 이후 4초 판별 간격을 유지합니다. 이전 60초 문맥은 별도로 보존합니다. 마지막 한 마디가 맞장구여도 앞 문장의 정보 필요성을 함께 판별합니다.
- 서버 판별 입력은 현재 묶음 마지막 1200자와 이전 문맥 마지막 400자를 사용하며 토큰 한도 오류 시 현재 묶음 마지막 600자로 재시도합니다. 이전의 현재 발화 600자·이전 문맥 800자보다 최근 대화에 더 많은 폭을 배정했습니다.
- 균형 기준은 후보 점수 0.40 이상·불필요 점수와 차이 0.08 이상입니다. 유용한 후보끼리 점수가 비슷하다는 이유만으로 생략하지 않습니다. 불필요와 근접한 후보(균형: 후보 0.28 이상, 불필요보다 낮아도 차이 0.06 이내)는 생성 모델이 마지막으로 검토하며 필요 없으면 `HINT_SKIP`을 허용합니다. 조용하게는 이 약한 후보 승격을 사용하지 않습니다. 점수는 교정된 정확도 수치가 아닙니다.
- AI 생성 중에 새 후보를 버리지 않고 최신 후보 하나를 대기시킵니다. 수락되지 않은 후보에는 중복·쿨다운 표시를 남기지 않습니다. 판별 기한은 발화 후 45초, 생성된 힌트 표시 기한은 발화 후 90초로 분리하고 생성 요청 제한은 75초로 늘렸습니다.
- 힌트 생성 지침에 '질문이 없어도 도움이 되는 배경 정보를 제시'하도록 명시하고, 후보 유형별 구체적인 작업을 지정했습니다. 대화 내용을 반복하는 일반 조언 대신 용어 정의·실제 답변 문구 등을 요청합니다.
- 힌트 상태를 상단 모드 선택 아래로 옮겼습니다. 판별에 사용한 발화 개수·글자 수, 임베딩 오류, 보류 등을 확인할 수 있습니다.

검증: AI 대기열 최신 항목 유지, 503·401·타임아웃에도 녹음 지속, 일반 모드 보관 정책 유지, 여러 문장과 맞장구를 포함한 묶음, 응답 수락 거부 후 재판별, 표시 기한 분리 테스트를 통과했습니다. 실제 JEV에서 누적 대화가 용어 설명 후보로 선별되는 것과 로컬 LLM에서 힌트 본문이 생성되는 것을 확인했습니다. 실제 대화의 선별과 설명의 정확도는 선택한 모델에 영향을 받습니다.

밝기 확인: SDK 0.0.16은 글자 밝기 `textColor` 0~4 조절을 지원합니다. 안경 전체 밝기 제어와 자동 감광의 배터리 절감량은 확인하지 않았으며 이번 버전에는 자동 감광을 구현하지 않았습니다.

## 1.4.0 — 주변 대화 힌트 자동 판별

현재 패키지는 **1.4.0**입니다. 새 판별 API가 포함된 Mac 게이트웨이를 완전히 종료·재실행하고 안경 앱도 업데이트해야 합니다.

- **AI 모드 응답 방식 → 힌트 자동 선별**이 기본입니다. 확정 전사·SQLite 저장은 계속하면서 로컬 EmbeddingGemma 2 + JEV로 `설명 / 과거 기억 / 답변 제안 / 사실 확인 / 불필요`를 분류합니다. AI에게 직접 질문한 문장만 고르는 방식이 아닙니다. 기존 연속 대화는 **모든 발화에 응답**으로 선택할 수 있습니다. 직접 입력한 텍스트 질문은 판별을 우회해 그대로 답변합니다.
- **힌트 적극성 → 조용하게 / 균형 / 적극적으로**를 제공합니다. JEV 점수와 차이를 이용하는 초기 휴리스틱이며 정확도나 확률 보장은 아닙니다. 필요성이 애매하면 생략합니다.
- 최근 60초 내 최대 16개 전사를 문맥으로 유지하고, 판별 입력은 실제 모델 토큰 한도를 고려해 마지막 문맥 800자와 현재 발화 600자로 제한합니다. 길이 오류 시 문맥 없이 현재 발화 마지막 300자로 재시도합니다.
- 판별은 최소 4초 간격, 동시에 1개만 수행합니다. 처리 중 새 발화는 최신 대기 항목 하나로 교체합니다. 힌트 후보를 수락한 뒤 15초 쉬며 최근 2분 내 같은 표현·유사 표현을 억제합니다. 단어가 완전히 다른 의역까지 의미 기반으로 중복 제거하는 기능은 아닙니다.
- 힌트는 기존 `/api/chat`의 계정별 기억·검색 경로로 생성합니다. 한국어 1~2문장으로 요청하고 표시 본문은 최대 140자로 제한합니다. 도움이 되지 않으면 생성 모델도 `HINT_SKIP`으로 생략할 수 있습니다. 힌트 생성 중에는 확정 전사를 계속 저장합니다.
- 발화 후 30초가 지난 판별·힌트, 모드 전환·정지 전의 응답은 표시하지 않습니다. 임베딩 사용 중이면 다음 발화에서 다시 판별하며, 미설치·비활성·API 오류는 설정의 힌트 상태에 표시하고 전사는 계속합니다. 비활성 시 모든 발화를 LLM에 보내는 식으로 자동 전환하지 않습니다.
- 주변 발화에서 실행 지시를 받아들이지 않도록 힌트 요청은 서버에서 읽기 전용 도구만 허용합니다. 기존 웹 채팅의 세션·취소 상태와 분리하고 생성된 힌트를 장기 기억에 자동 저장하지 않습니다. 원래 전사는 기존대로 SQLite에 남습니다.

검증: 힌트 생략/선별과 저장 독립성, 직접 질문 우회, 대기 병합, 중복·쿨다운·기한 만료·모드 취소, 오류 격리, 읽기 전용 도구 실행 제한, 일반 채팅 응답 ID 미연결 테스트를 통과했습니다. 실제 설치된 JEV 한국어 예문에서 인사·격려 2개는 생략하고 용어 설명 2개와 답변 추천 1개를 선별했습니다. 약속 회상 예문 1개는 놓쳤습니다. 최초 분류는 약 0.91초, 재사용은 약 35~43ms였으며 모델 초기 로딩·G2 네트워크·최종 힌트 생성 시간은 제외한 수치입니다. 실제 대화에서는 오선별·누락이 있을 수 있습니다.

## 1.3.8 — 전사 적체 시 음성 보존과 재시도

현재 패키지는 **1.3.8**입니다. 안경 앱 업데이트만 필요하며 서버 재시작은 필요하지 않습니다.

- 대기 음성 2개 초과 시 이전 항목을 버리던 동작을 제거했습니다. 타임아웃을 모드 취소와 구분하고 같은 segment ID로 재시도합니다. 서버 SQLite는 같은 사용자·segment ID의 중복 저장을 막습니다.
- 네트워크 오류, HTTP 408/425/429/5xx에는 짧은 대기를 두고 최대 3회 추가 재시도합니다. 인증·잘못된 요청·저장 미확인 오류는 음성을 보관한 채 녹음을 정지하고 원인을 표시합니다. 다시 녹음하면 보관 음성도 재시도합니다.
- 최종 전사 응답 제한을 20초에서 120초로 늘렸습니다. 장시간 추론·서버 대기를 허용하되 응답이 없으면 음성을 보존하고 재시도합니다. 일반적인 실시간 지연이 줄어든다는 의미는 아닙니다.
- 대기 PCM이 약 120초 분량 또는 64개에 도달하면 새 녹음을 일시정지하고 보관 음성을 처리합니다. 오래된 항목을 지우지 않습니다. 남은 발화의 마감 처리로 한 구간 정도 추가될 수 있습니다. 모드 전환은 기존대로 이전 모드의 미처리 작업을 취소합니다.
- 보관 음성은 앱 메모리에 있으며 앱 종료 후에는 복원되지 않습니다. 미저장 오류 메시지에 이 제한을 표시합니다.

검증: 6개 적체 시 순서·음성 보존, 503 자동 재시도, 타임아웃 음성 보존, 모드 전환 후 오래된 응답이 새 항목을 지우지 않는지, 401 보관, 적체 상한에서 녹음 일시정지를 테스트했습니다. 실제 장시간 G2 전사는 업데이트 후 확인이 필요합니다.

주변 대화에서 필요한 정보만 제안하는 힌트 모드는 [설계안](HINT_MODE_PLAN.md)에 정리했습니다. 1.3.8은 전사 안정화 수정이며 힌트 모드의 의미 판별은 아직 구현하지 않았습니다.

## 1.3.6 — 큐 병목 제거, 모드 전환 시 대기열 정리 및 녹음/전사 응답성 개선

현재 패키지는 **1.3.6**, 기본 API 주소는 `http://192.168.1.4:2806`입니다.

- **전사 큐(`pendingClips`) 및 AI 큐(`pendingAI`) 병목 해소**:
  - 전사 대기열(`pendingClips`) 최대 길이를 2개로 제한하고 20초 타임아웃을 적용해 지연 시 오래된 음성 조각이 쌓여 멈추는 현상을 방지했습니다.
  - AI 응답 중 추가 발화가 들어올 때 대기열(`pendingAI`)에 여러 건이 중복 적체되지 않도록 1건으로 병합(coalesce) 처리합니다.
  - 이전 전사/임시 자막(`previewBusy`/`draining`) 처리 중에도 새 녹음 시작이 차단되지 않고 즉시 임시 자막 요청을 취소(`AbortController`)하고 마이크를 열도록 수정했습니다.
- **모드 전환(`setGlassesMode`) 시 상태 초기화**:
  - 전사 / AI / 번역 모드 전환 시 이전 모드의 미처리 음성 큐(`pendingClips`), 진행 중인 임시 자막/전사 요청, AI 대기열(`pendingAI`) 및 스트리밍 요청을 즉시 취소하여 모드 전환 직후 멈춤 현상을 해결했습니다.
  - 녹음 중 수동(전사 모드) ↔ 연속 감지(AI/번역 모드) 전환 시 오디오 버퍼와 타이머를 새 모드에 맞게 즉시 재설정합니다.
- **번역 모드 인식 언어 선택 및 Whisper 워커 재시작 방지**:
  - 번역 모드에 **인식 언어(`#translate-source-lang`)** 선택을 추가하고 기본값을 2자리 표준 언어 코드로 전달하여 구버전 서버에서도 Whisper 워커 재시작(약 10초 멈춤) 없이 즉시 인식되도록 개선했습니다.

## 1.3.5 — 전사 · AI · 번역 3가지 안경 모드 및 번역 언어 호환성 수정

현재 패키지는 **1.3.5**, 기본 API 주소는 `http://192.168.1.4:2806`입니다.

- **전사 모드 (`transcript`)**: 기존과 동일한 전사 및 AI 범용 모드 (수동 녹음 후 AI 질문 또는 연속 전사 중 호출어로 AI 호출).
- **AI 모드 (`ai`)**: 트리거 워드(호출어) 없이 연속으로 발화를 인식하여 발화가 끝날 때마다 곧바로 AI와 대화합니다.
- **번역 모드 (`translate`)**: 들어오는 음성의 언어를 자동으로 감지(`language: auto`, 재시작 전 구버전 서버에서는 유효 언어 코드로 자동 폴백)하여 설정한 목표 언어(한국어, 영어, 일본어, 중국어, 스페인어, 프랑스어, 독일어, 베트남어, 태국어)로 번역하고, 이에 대한 **긍정 / 부정 / 중립** 추천 답변을 **들어오는 언어(원문 언어) 및 번역문**으로 함께 표시합니다.
- 번역 모드에서 `language: auto` 미지원 구버전 서버 응답 시 실패한 클립이 큐에 남아 다른 모드까지 전사 오류를 유발하던 문제를 수정했습니다.
- 안경 컨텍스트 메뉴(`menuObject`), 안경 터치바 길게 누르기(`LONG_PRESS_EVENT`), 휴대폰 화면 상단 모드 탭에서 즉시 모드를 전환할 수 있습니다.

## 1.3.2 — LM Studio 대화 연결과 텍스트 입력

현재 패키지는 **1.3.2**입니다. 이번 버전은 Mac 게이트웨이를 완전히 종료·재실행하고 안경 앱 패키지도 업데이트해야 합니다.

- 계정의 실제 LLM 모드를 조회하여 LM Studio에는 `input`/`system_prompt`, OpenAI 호환 서버에는 `messages`를 보냅니다. `input is required` 오류를 수정했습니다. 기존 게이트웨이의 도구·메모리·EmbeddingGemma 2 + JEV 경로를 그대로 사용합니다.

- 마이크 아래 텍스트 질문 입력창과 전송 버튼을 추가했습니다. 호출어 없이 같은 AI 대기열로 질문을 보내며, 답변은 휴대폰과 안경 화면에 표시합니다.
- 하단 기본 여백 120px과 안전 영역, 키보드가 가리는 높이를 반영한 추가 여백을 적용했습니다. 입력 글자 크기를 16px로 맞춰 iPhone의 입력 시 자동 확대를 줄였습니다.

검증: 양쪽 모드의 요청 형식, LM Studio 스트림·최종 답변 교체, 오류 원문과 빈 답변 표시, 텍스트 입력 대기열, 녹음 정지 회귀 테스트를 통과했습니다. 실제 iPhone 키보드와 G2 화면은 업데이트 후 확인이 필요합니다.

## 1.3.1 — 두 번째 탭으로 녹음 정지

1.3.1의 기본 API 주소는 `http://192.168.1.4:2806`입니다. 안경 앱 패키지만 업데이트하면 적용되며 Mac 게이트웨이 재시작은 필요하지 않습니다.

## 1.3.0 — 말하는 도중 자막 갱신

1.3.0의 기본 API 주소는 `http://192.168.1.4:2806`입니다. 이번 버전은 게이트웨이와 안경 앱을 모두 업데이트해야 합니다.

- **음성 모드 → 실시간 전사**에서 마이크를 시작하면, 최초 약 1.2초 오디오와 0.4초 이상의 음성을 확보한 뒤 임시 자막을 요청합니다. 이후 약 1초 간격으로 최신 누적 오디오를 전사합니다. 처리 지연 시에는 최신 초안 하나만 대기합니다.
- LocalAgreement-2로 연속 두 결과의 일치하는 앞부분을 안정화합니다. 수정될 수 있는 꼬리에는 `…`를 표시합니다. 발화 종료 후 전체 문장으로 보정하며, 임시 자막은 저장·트리거 판정에 사용하지 않습니다.
- 최종 결과는 기존 SQLite에 저장합니다. AI 답변은 별도 큐로 처리하므로 답변 생성 중에도 전사를 계속합니다. 답변 아래에 최신 자막을 짧게 표시하고, 답변 완료 약 8초 뒤 자막 화면으로 돌아갑니다.
- AI 호출어는 **쉼표로 여러 개** 입력할 수 있습니다. 예: `웬즈데이, 웬즈 데이, 웸즈 데이`. 띄어쓰기와 영문 대소문자를 무시하므로 앞의 두 표현은 같은 호출어입니다. 정규화 후 최대 8개, 각각 40자까지 등록합니다. 등록한 표현만 비교하며 임의의 유사 단어를 넓게 추측하지 않습니다.
- 상태 줄 왼쪽에는 `전사 저장됨 · AI 호출어: 웬즈데이`, 오른쪽에는 `16:14 / 75%`를 표시합니다. 호출어가 여러 개면 첫 표현을 대표로 표시하고, 긴 문구는 말줄임 처리합니다. 본문에는 전사·답변만 표시합니다.
- 마이크를 열기 전에 모델을 준비합니다. 처음 모델을 불러올 때 준비 시간이 필요하며, 준비가 끝난 뒤 녹음을 시작합니다.

검증: 실제 MLX GPU에서 한국어 합성 음성 1.3초 → 2.3초 → 3.3초 입력에 따라 문장이 확장됐고 각 임시 추론은 약 0.39~0.41초였습니다. 초안 중 DB 미기록, 최종 저장, 초안 호출어 무시, 종료 후 늦은 응답 무시, LLM 대기 중 전사 지속을 테스트했습니다. 실제 G2 BLE·Wi-Fi 상태에 따른 지연과 장시간 동작은 기기에서 확인해야 합니다.

전송은 Bearer 인증을 사용하는 HTTP 누적 스냅샷 방식이며 WebSocket은 추가하지 않았습니다. API는 `/api/stt/warmup`(준비), `/api/stt/preview`(화면 전용), `/api/stt/transcribe`(최종 저장)로 나뉩니다. [구현 상세](STREAMING_PLAN.md)를 참고하세요.

이번 Mac에는 MLX 모델과 런타임을 설치하고 실제 GPU 추론, 잡음 제외, 트리거 판정, 사용자별 SQLite 저장까지 검증했습니다. 게이트웨이를 다시 시작하고 안경 앱을 새 패키지로 업데이트해야 모든 변경이 적용됩니다. 기존 EmbeddingGemma 2 + JEV, 도구, 장기 기억 처리는 계속 기존 `/api/chat` 경로를 사용합니다.

## 1.1.1 — 음성 필터, 설정 유지, 전사 기록 창

현재 패키지는 1.1.1이며 기본 서버 주소는 `http://192.168.1.4:2806`입니다.

- 전사 기록은 별도 모달에서 열고 기록 영역만 스크롤합니다. 닫으면 설정 화면으로 돌아옵니다. 긴 기록으로 설정 저장 버튼이 밀려 내려가지 않습니다.

## 1.1.0 — 연속 전사와 AI 트리거

현재 생성한 `dkst-ai-gateway.ehpk` 1.1.0의 서버 주소는 `http://192.168.1.4:2806`입니다. 게이트웨이 서버도 이번 버전으로 다시 실행해야 합니다.

1. 로그인 후 모델을 선택하고 **음성 모드 → 연속 전사**를 선택합니다.
2. **AI 트리거 워드**를 입력하고 **설정 저장**을 누릅니다. 기본값은 `이븐`입니다.
3. 마이크 버튼 또는 G2를 한 번 탭하면 녹음을 시작하고 다시 탭하면 중지합니다.
4. 일반 발화는 전사 후 날짜·시각과 함께 기존 `memory/memory.db`의 `stt_transcripts` 테이블에 저장됩니다. 마이크 원본 오디오는 DB에 저장하지 않습니다.
5. `이븐 오늘 일정을 알려줘`처럼 트리거가 포함되면 뒤의 질문을 기존 `/api/chat`으로 보냅니다. 트리거만 말했다면 다음 발화를 질문으로 사용합니다. 최근 전사 8개를 대화 맥락으로 전달하며, 사용자별 도구·장기 기억·EmbeddingGemma 2 + JEV 설정은 기존 서버가 처리합니다. 전사 전체를 장기 기억에 자동 등록하지는 않습니다.
6. **날짜별 전사 기록 → 기록 보기 / TXT 저장**으로 본인 계정의 기록을 확인합니다. 날짜는 휴대폰의 시간대를 기준으로 조회합니다. 향후 요약 기능을 붙일 수 있도록 원문과 시각을 분리 저장하며, 자동 요약은 아직 없습니다.

발화는 약 0.9초 무음 또는 최대 12초 단위로 구분합니다. 전사 결과는 발화 구간이 끝난 뒤 표시되므로 단어 단위 실시간 자막과는 지연이 다릅니다. 연속 녹음 중 AI 답변을 처리하는 동안에도 다음 발화를 수신합니다. 처리 대기가 12구간을 넘으면 녹음을 중지합니다. 오류가 난 음성 구간은 앱이 열린 동안 재시도 대기하며, 서버에 저장되지 않은 상태에서 앱을 닫으면 사라집니다. 연속 모드의 TTS는 재녹음을 방지하기 위해 재생하지 않습니다.

Whisper Base를 실제 ONNX 런타임에 연결했습니다. 16 kHz mono PCM16/WAV를 지원하며 모델은 서버에서 오프라인 실행됩니다. 모델 관리자에서 STT를 설치할 때 Python 3.12 환경과 Optimum ONNX 런타임도 설치합니다. 기존 모델만 설치한 사용자는 STT를 다시 다운로드해 빠진 보조 파일과 런타임을 설치해야 합니다. 이번 Mac에는 설치와 한국어 합성 음성 테스트까지 완료했습니다. 일부 단어가 잘못 인식될 수 있습니다.

**호출어의 범위:** 여기서 저장하는 트리거는 이 앱이 열린 상태에서 연속 녹음할 때 작동합니다. 이를 Even AI의 전역 앱 실행 단축어로 자동 등록하는 공개 SDK API는 확인하지 못했습니다. EDITH의 공개 manifest에도 별도 호출어 선언은 보이지 않습니다. Even AI의 Shortcut center 및 실제 기기 동작은 별도로 확인해야 합니다. 앱을 닫은 상태의 호출이나 아이폰 잠금 상태의 지속 녹음은 보장하지 않습니다.

## 지금 G2에서 실행하기

1. 휴대폰의 Even Realities 앱과 같은 계정으로 <https://hub.evenrealities.com/login>에 로그인합니다.
2. 휴대폰 앱을 완전히 종료한 뒤 다시 열고, Even Hub 탭의 개발자 메뉴에서 **Scan QR**을 선택합니다.
3. 휴대폰을 서버에 접근할 수 있는 Wi-Fi에 연결하고 아래 QR을 스캔합니다. G2는 휴대폰 앱에 연결되어 있어야 합니다.

   ![G2 개발 미리보기 QR](g2-preview-qr.png)

   QR 주소: <https://192.168.1.4:8080/plugins/even-realities/>

4. 앱의 서버 주소가 `https://192.168.1.4:8080`인지 확인하고 게이트웨이 계정으로 로그인한 뒤 모델을 선택하고 설정을 저장합니다.
5. G2 또는 화면의 마이크 버튼을 한 번 눌러 녹음하고 다시 눌러 전송합니다. G2를 두 번 탭하면 시스템 종료 확인창을 엽니다.

게이트웨이는 계속 실행되어 있어야 합니다. 서버는 실행 작업 폴더 아래의 `plugins/even-realities`를 제공하므로 이 폴더를 유지하세요. 음성 인식에는 게이트웨이 Asset Manager에서 STT 모델을 먼저 설치해야 합니다. G2에는 스피커가 없으며 TTS는 휴대폰/이어폰에서 재생됩니다. 자동 재생이 제한될 수 있어 기본값은 꺼짐입니다.

### 인증서 때문에 열리지 않을 때

확인된 서버는 HTTP로 접근한 앱 페이지를 HTTPS로 리다이렉트하며, HTTPS에는 자체 서명 인증서가 적용되어 있습니다. 휴대폰에서 이 인증서를 신뢰하지 않으면 Even 앱의 WebView에서도 로드가 실패할 수 있습니다. 휴대폰에서 신뢰되는 인증서와 그 인증서에 맞는 주소를 사용하세요. 일반 브라우저의 경고를 한 번 통과하는 것만으로 Even 앱에서도 신뢰되는 것은 아닙니다. 주소를 바꾸면 QR도 다시 생성해야 합니다.

### 설치 앱에서 `Load failed`가 나올 때

`Load failed`는 HTTP 401 인증 오류와 다릅니다. 설치 앱은 휴대폰의 loopback WebView 주소에서 실행되므로 게이트웨이 API에 CORS 처리가 필요합니다. 게이트웨이의 `evenHubCORS` 미들웨어는 앱에서 사용하는 API에 한해 loopback Origin을 허용하고 로그인 사전 요청에 204로 응답합니다. 인증에는 세션 쿠키 대신 명시적인 Bearer 토큰을 사용합니다. 이 서버 수정은 게이트웨이 실행 파일을 다시 빌드하고 앱을 완전히 종료한 뒤 실행해야 적용됩니다. 안경 앱 1.0.1은 다시 설치하지 않아도 이 서버 수정을 사용할 수 있습니다.

## 수정 후 빌드와 QR 재생성

이 폴더에서 실행합니다. Node.js 20.17+, 22.13+ 또는 23.5+가 필요합니다.

```sh
npm ci
npm run build -- --server https://192.168.1.4:8080
npm test
npm run qr -- --url https://192.168.1.4:8080/plugins/even-realities/ --external
```

`bundle.js`에는 공식 SDK가 포함됩니다. `index.html`만 복사하거나 `plugin.js`만 직접 로드하면 안 됩니다. `npm run build`의 `--server`를 생략하면 페이지를 연 서버 주소를 기본값으로 사용합니다.

## 개인 설치용 패키지

아래 명령은 예시 서버 주소 `http://192.168.1.4:8080`을 사용합니다. 이번에 생성한 1.1.0 패키지의 실제 주소는 위의 1.1.0 절을 참고하세요. HTTPS 자체 서명 인증서 때문에 아이폰 Prototype Mode의 페이지 로딩이 막히는 경우를 피하기 위한 로컬 Wi-Fi 테스트용입니다. 앱 파일은 패키지 안에서 로드하고 API만 HTTP로 호출합니다. HTTP API에는 TLS 암호화가 없으므로 신뢰하는 로컬 Wi-Fi에서 사용하세요. 실제 아이폰의 HTTP 허용 정책과 G2 동작은 설치 후 확인해야 합니다.

1.0.2는 LM Studio의 `key`와 `display_name` 필드를 지원하여 `[object Object]` 모델명 표시를 수정하고, 대화 요청에는 실제 모델 ID를 전달합니다.

웹 허브에서 프로젝트의 Builds에 패키지를 업로드한 뒤, 같은 계정의 아이폰 Even 앱에서 **Me → Apps → Private builds**를 열어 설치합니다. 개인 빌드는 휴대폰에서 실행하는 용도입니다. 안경 메뉴에서 실행하려면 베타 배포와 본인 계정의 테스터 등록이 필요합니다.

```sh
npm run pack -- http://192.168.1.4:8080
```

`dkst-ai-gateway.ehpk`가 생성됩니다. 서버 주소는 번들의 기본값과 `dist/app.json`의 네트워크 허용 목록에 함께 반영됩니다. 패키지를 배포할 때도 실제로 휴대폰에서 접근 가능한 서버 주소가 필요합니다. 생성된 파일을 공식 개발자 포털에서 개인 빌드로 등록한 뒤 같은 계정의 휴대폰 앱에서 설치할 수 있습니다. QR 개발 미리보기에는 이 업로드 과정이 필요하지 않습니다. 이 프로젝트에서는 패키지를 로컬에만 생성하며 업로드하지 않습니다.

빌드·패키징 및 모의 브리지 검증을 완료했습니다. 실제 G2에서의 녹음, 한글 표시, Bluetooth 연결, 휴대폰 인증서 신뢰는 기기에서 확인해야 합니다.
