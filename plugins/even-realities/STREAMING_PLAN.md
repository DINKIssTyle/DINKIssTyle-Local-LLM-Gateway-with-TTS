# 실시간 전사 설계안

상태: **1.3.0에 임시 자막·LocalAgreement-2·최종 보정·AI 큐 분리를 구현했습니다.**

전송은 인증된 HTTP POST 누적 스냅샷 방식입니다. `/api/stt/preview`는 저장·트리거 판정을 하지 않고, `/api/stt/transcribe`만 최종 저장을 수행합니다. 프레임별 WebSocket 전송과 서버 상주 VAD 세션은 이번 버전에 포함하지 않았습니다. 발화 경계는 기존 클라이언트 구간 분리기를 사용하고 서버에서 Silero가 각 누적 구간을 검사합니다.

## 권장 구성

기존 **MLX Whisper Large-v3-Turbo 한 모델**을 상주시킨 채, **임시 자막 → LocalAgreement-2로 표시 안정화 → 발화 종료 후 최종 전사**를 수행합니다. 최종 문장만 기존 기록·트리거·채팅 경로로 보냅니다. Tiny/Base를 추가하는 구성은 실제 부하 측정에서 필요한 경우에만 검토합니다.

```text
G2 PCM → 클라이언트 발화 버퍼 → 인증된 HTTP 누적 스냅샷 + Silero 검사
                              ├─ 약 1초마다 최신 오디오로 Turbo 추론
                              │    → 이전 가설과 접두부 비교 → 화면용 자막
                              └─ 발화 종료 → 전체 발화 최종 추론
                                   → 품질 검사 → SQLite 저장 → 트리거 판정
                                                          → 기존 /api/chat
```

## 초기 운영값

- PCM 수신: SDK의 16 kHz mono PCM16 프레임을 버퍼링합니다. 서버에는 약 1초 간격으로 최신 누적 스냅샷과 캡처 시점을 전달합니다.
- 임시 추론: 음성이 충분히 쌓인 뒤 약 1초 간격으로 시작합니다. 첫 초안은 최소 1.2초 오디오와 약 0.4초의 감지된 음성을 확보한 후 시도합니다.
- 추론 중 새 오디오가 오면 최신 스냅샷 하나만 대기시킵니다. 오래된 초안을 순서대로 처리하지 않습니다.
- 발화 종료: 우선 약 0.9초의 무음을 유지합니다. 쉼표·마침표는 ASR의 추정 결과이며, VAD는 음성과 무음을 판별합니다.
- 기본 발화 버퍼 상한: 기존의 약 12초를 출발점으로 삼습니다. 긴 발화의 중간 분할은 실제 한국어 음성으로 별도 검증합니다.
- 최종 추론은 다음 임시 추론보다 우선합니다. 이미 실행 중인 GPU 작업을 강제로 중단하지 않고, 완료 시 오래된 응답을 버립니다.
- 위 수치는 초기 설정안이며 보장 지연 시간이 아닙니다. 단일 전사 벤치마크와 반복 추론의 전체 지연은 따로 측정합니다.

## 자막 상태와 화면

- **임시:** 수정될 수 있는 화면 전용 가설입니다.
- **안정화:** 연속 두 가설에서 일치하는 앞부분입니다. 한국어는 Unicode NFC 정규화 후 비교하며, 불완전한 단어 끝과 문장부호 변경을 보수적으로 처리합니다.
- **최종:** 발화 종료 후 전체 오디오를 다시 인식하고 품질 검사를 통과한 결과입니다. 안정화된 접두부도 최종 문장으로 교체할 수 있습니다.

합의는 정확도의 증명이 아닙니다. 같은 오인식이 두 번 나올 수 있으므로 음성 감지, 낮은 신뢰도, 반복 문자열 검사는 모든 단계에서 유지합니다.

안경 화면의 상태 줄은 `16:14 / 75%` 한 줄로 유지합니다. 본문에 최근 자막을 표시하고 임시 꼬리는 짧게 구분합니다. 별도 설명 제목과 페이지 번호로 줄을 추가하지 않습니다. 문자가 실제로 바뀔 때만 HUD를 갱신하며, BLE 화면 전송은 기존처럼 직렬화·병합합니다.

AI 답변을 표시하는 동안에도 오디오 수신과 전사는 계속합니다. 자막 도착이 생성 중인 답변을 즉시 덮어쓰지 않도록 자막 표시와 답변 표시의 상태를 분리합니다. 답변 열람·자막 복귀 동작은 기기에서 확인합니다.

## 서버와 저장 경계

`/api/stt/preview`와 `/api/stt/transcribe`는 오디오 검증·추론 코드를 공유하되, preview는 DB 기록과 호출어 판정 전에 반환합니다. 최종 경로만 기존 저장·트리거 처리를 수행합니다.

- 세션은 인증된 사용자에 귀속시킵니다. WebSocket을 쓸 경우 토큰을 URL에 넣지 않고 연결 직후 인증한 다음 오디오를 받습니다.
- 모든 응답에 `sessionId`, `utteranceId`, `revision`, 오디오 오프셋, 상태를 포함합니다. 이전 세션·이전 revision의 결과는 화면에 반영하지 않습니다.
- 최종 결과는 안정적인 발화 ID로 SQLite에 중복 없이 저장합니다. 트리거 작업도 같은 ID로 중복 등록을 방지합니다.
- 임시 트리거에는 AI가 반응하지 않습니다. 최종 문장이 확정된 뒤 한 번 판정하고, 기존 채팅 API를 통해 도구·메모리·EmbeddingGemma 2 + JEV를 사용합니다.
- 음성 추론 큐와 AI 답변 큐를 분리합니다. 느린 LLM/도구 실행이 다음 전사를 막지 않도록 합니다.
- 버퍼는 최종 확정된 오디오 경계에서 줄입니다. 이전 전사 전체를 `initial_prompt`로 누적하지 않습니다. 필요하면 검증된 최근 최종 문장만 제한적으로 사용합니다.
- 연결 해제·재연결·중지·앱 종료 시 남은 오디오를 확정하거나 미저장 상태를 분명히 표시합니다. 원본 오디오의 영구 저장은 기본값으로 추가하지 않습니다.

## 구현 결과와 후속 검토

1. 세션/발화/revision으로 늦은 응답을 제외하고, 임시 자막의 저장·AI 호출을 차단했습니다.
2. 1.2초 오디오와 0.4초 이상 음성이 쌓이면 첫 초안을 요청하고, 이후 약 1초마다 갱신합니다. 이전 초안 처리가 늦으면 최신 스냅샷 하나만 유지하며 최종 전사를 먼저 처리합니다.
3. LocalAgreement-2는 화면 표시만 안정화합니다. 발화 종료 후 결과로 전체 문장을 보정합니다.
4. AI 답변은 별도 큐에서 처리합니다. 답변 생성 중에도 전사를 계속하고, 답변 아래에 최근 자막을 짧게 표시합니다. 답변 완료 약 8초 후 자막 화면으로 복귀합니다.
5. 원래 계획의 서버 상주 VAD/프레임 스트리밍, 세밀한 장기 발화 분할은 후속 검토 항목입니다.

검증: 실제 MLX 한국어 합성 음성의 1.3초/2.3초/3.3초 누적 입력에서 임시 자막이 확장됐고 각 요청은 약 0.39~0.41초였습니다. 초안 동안 DB는 비어 있었으며 최종 요청에서만 저장됐습니다. 모의 G2 테스트에서 초안 호출어 무시, 종료 후 늦은 응답 무시, LLM 대기 중 전사 지속을 확인했습니다.

검증 항목: 첫 자막/안정화/최종 확정 지연의 중앙값·상위 지연, 한국어 오류율, 임시 자막 수정 횟수, 중복 저장·중복 AI 호출, 장시간 큐 길이, Wi-Fi 끊김, 아이폰 잠금/복귀, BLE 화면 갱신, LLM 및 JEV 동시 실행 시 GPU 부하입니다. 임시 자막을 빠르게 표시하면서 최종 정확도를 기존 Turbo보다 떨어뜨리지 않는 것을 목표로 합니다.
