# AI 힌트 2.17.0 이후 검토 — 2026-11-16

## 저장 여부와 검토 범위

- SQLite `stt_transcripts`에는 인식한 음성 전사와 호출어 여부가 저장된다. AI 힌트 본문·판별 결과·생략 이유·화면 표시 완료는 저장하지 않는다.
- 폰의 ‘최근 힌트 · 표시 이유’는 실행 중 최근 12건의 제목·이유만 메모리에 유지하며 본문도 저장하지 않는다.
- 안경 요청은 일반 웹 채팅 세션/장기 기억 저장에서 분리되어 있다. 따라서 `chat_events`를 안경 힌트 표시 이력으로 사용할 수 없다.
- LM Studio 로그에 남은 입력·응답을 읽기 전용으로 검토했다. 2.17.0의 최근 문맥·번호 근거 프롬프트가 실제로 사용된 2026-11-16 00:03:12~00:49:46 KST의 앱 요청을 대상으로 했다. 합성 검증에 사용한 E2B 요청은 제외하고 앱이 사용한 E4B 요청을 집계했다. 이는 앱 버전 자체의 영구 기록을 확인한 것이 아니라 프롬프트로 식별한 범위다.
- 원문 전사·모델의 상세 응답·인증 정보는 이 보고서나 저장소 테스트 자료에 복사하지 않았다. 분석 중간 자료는 `/private/tmp`에만 두었다.

68개 hint=true의 분류는 요약 52, 핵심 12, 용어 3, 확인 1이었다. 일정은 이 범위의 긍정 판별에서 없었다. hint=true 23건은 evidence=0, 20건은 빈 topic을 반환했다. 두 집합은 겹치므로 합산하면 안 된다. 400건의 생성 완료 로그는 모두 stop으로 끝났으며 요청→마지막 패킷은 초 단위 로그상 대체로 1~3초였다. 이 표본의 주원인을 단순 LLM 시간 초과로 보기는 어렵다.

14개 writer 응답을 서버의 hint_grounding 자료와 현재 검증기로 재검사하면, 요약 10건은 adds_information=false 때문에 즉시 거부된다. 외부 자료 힌트 2건 중 1건은 검증 주제와 제목을 바꾸어 거부되고 1건은 통과한다. 요약 1건과 외부 자료 1건이 이 검사에서 통과하더라도, 실제 안경 화면에 표시됐다는 뜻은 아니다. 이후의 취소·전사 수정·중복·SDK 단계는 당시의 영구 이벤트가 없어 확정할 수 없다.

## 확인된 코드 문제

1. **유용한 요약과 ‘새 외부 사실’을 같은 불리언으로 취급한다.** 모델이 points에 내용을 작성하고도 이미 대화에 있던 정보라는 이유로 adds_information=false를 쓰면 검증기가 원문 근거를 보기 전에 버린다. 요약의 도움은 새로운 외부 사실이 아니라 압축·연결에 있으므로 모드별 수용 기준을 분리해야 한다. false를 무조건 true로 바꾸거나 오인식 요약을 전부 표시하는 방식은 피해야 한다.
2. **hint=true인데 근거 0 또는 빈 제목을 허용하는 판별 스키마다.** 0은 생략용 번호이지만 hint=true와 동시에 나올 수 있다. 후처리가 거부해도 사용자는 이유를 지속적으로 확인할 수 없다. 긍정/생략 구조를 분리하거나 제한된 형식 복구가 필요하다. 없는 근거를 자동 선택하면 안 된다.
3. **이전 문장 근거를 마지막 프리뷰에서만 검사하는 경로가 남았다.** `decide` 안의 사전 relevant 검사에서 evidenceEntries가 아직 구성되지 않은 job을 검사한다. 앞 문장이 남아 있어도 최신 프리뷰가 그 문구를 포함하지 않으면 transcript_changed로 거부한다. 합성 2문장 재현에서도 확인됐다. 실제 교정/철회에 대한 보호는 유지하면서 최근 문맥의 해당 원문 항목과 비교해야 한다.
4. **요약 위주의 소극적 선별과 주제 혼동도 있다.** 과학 용어가 명확히 나오는 구간을 생략하거나, 설명에 쓰인 비유를 주제로 잘못 잡은 출력이 확인됐다. 요약의 표시 조건을 고치는 것만으로 용어·사실 확인의 선택 품질이 해결되지는 않는다.
5. **본문이 완성되지 않은 출력도 있다.** 원문 증거를 길게 되풀이하는 points 구조는 출력 길이를 늘린다. 종료 이유·본문 크기·중단 지점을 기록하고, 짧은 원문 번호/범위로 근거를 표현하도록 검토할 필요가 있다.

## 다음 수정 우선순위

1. 앞 문장 근거의 프리뷰 검증 오류와 긍정 판별의 빈 근거/제목 문제를 재현 테스트로 고친다.
2. 대화 요약·일정의 ‘유용한 정리’ 기준을 외부 사실 추가 기준과 분리한다. 실제 원문·조건·부정·숫자 보호는 유지한다.
3. 제한된 대표 사례로 ‘용어 설명/요약/외부 확인’의 선택을 비교하고, 불필요한 요약 및 비유의 주제 오인식을 줄인다.
4. 전사 내용에 AI 문구를 섞지 않고 **별도 힌트 이벤트**로 판별·생략 사유·생성·폰 표시·안경 전송 완료를 기록한다. 권한·보관량·보관 기간을 정하고, 전사/장기 기억/다음 판별 문맥에 자동 재주입하지 않는다. 모델 생성 로그만으로 표시 성공이라고 기록해서는 안 된다.

이 문서의 분석은 읽기 전용으로 수행했다. 이후 사용자 요청으로 2.19.0에서 근거 검사·요약 수용·형식 재판별과 별도 처리 이력을 구현했으며, 자세한 동작과 검증은 README의 2.19.0 항목에 기록했다. 과거 실제 표시 이력이 소급 생성되는 것은 아니다.
