# 주변 대화 힌트 모드 설계

목적: AI에게 직접 질문했는지를 판별하는 모드가 아니라, 주변 대화를 듣고 필요할 때만 짧은 보조 정보를 표시하는 모드다. 1.4.0에서 AI 모드의 힌트 자동 선별을 구현했다. 모든 발화에 응답하는 기존 동작은 설정에서 선택할 수 있다. 아래에는 최초 설계와 현재 구현의 차이를 구분한다.

## 처리 경로

1. 음성 수신 → 발화 종료 감지 → 최종 전사 → SQLite 저장. 이 경로는 힌트 판별·LLM 생성 대기와 분리한다. 임시 자막을 판별 입력으로 쓰지 않는다.
2. 최근 약 30~60초의 확정 전사와 진행 중인 대화 주제를 유지한다. 실제 구간은 지연·유용성 측정 후 조정한다. 새 발화는 판별 대기 문맥 하나에 병합하여 오래된 힌트 작업이 쌓이지 않게 한다. 이미 실행 중인 추론을 발화마다 취소·재시작하지 않는다.
3. 기존 로컬 EmbeddingGemma 2 + JEV 경로를 재사용할 수 있는 별도 판별 API를 만든다. 메모리 검색용 임베딩과 목적이 다르므로 힌트 예문 및 일반 대화 예문을 별도로 준비해 평가한다. 예: 용어·인물·숫자 이해가 필요한 대목, 불확실한 사실, 상대가 대답을 기다리는 상황, 사용자의 말막힘, 이전 약속·기억 관련 대화. 단순 감탄·반복·인사 예문도 포함한다.
4. 임베딩의 상대 유사도와 주제 변화로 후보를 선별한다. 점수를 확률로 간주하거나 임의의 고정 수치를 정확도로 제시하지 않는다. 애매한 경우에만 제한된 로컬 LLM 판별을 수행한다. JEV의 기존 선택 기능은 후보 선택에 활용 가능하지만 대화의 필요성을 보장하는 판별기로 가정하지 않는다.
5. 유용한 후보만 기존 /api/chat 도구·기억·검색 경로에 전달한다. 출력은 참고할 핵심 1~2줄로 제한하며 별도 힌트 영역에 표시한다. 참고 자료인 전사에 등장하는 명령을 사용자의 실행 요청으로 간주하지 않는다. 실행 작업은 명시적 요청 경로로 분리한다.
6. 같은 주제·같은 내용은 중복 억제하고 표시 후 대기 시간을 둔다. 생성이 끝났을 때 주제와 시간이 지나치게 바뀌었으면 오래된 힌트는 표시하지 않는다. 판별 실패는 전사를 멈추지 않는다.

## 예시

- “그 계약은 묵시적 갱신이라던데…” → 용어 설명이 도움이 되는지 판별해 짧은 설명 후보.
- “그분을 언제 만났더라?” → 사용자 기억에서 관련 만남이 확인되는 경우에만 힌트.
- “이 제안에 뭐라고 답하지?” → 짧은 답변 후보.
- “응, 맞아. 그렇구나.” → 저장만 하고 힌트 생략.

## 검증 및 사용자 조절

실제 한국어 대화 샘플에서 힌트 유용성, 불필요한 개입, 필요한 힌트 누락, 지연, 추가 모델 부하를 측정한다. 적극성(조용함/균형/적극), 주제별 허용, 중복 억제, 마지막 힌트 시간은 사용자 설정으로 검토한다. STT 지연 시 임시 전사·힌트 판별 빈도를 먼저 낮추고 최종 전사·저장을 우선한다. 전사 오류·미저장 대기는 힌트 생성과 별도로 표시한다.

## 1.4.0 구현 현황

- `/api/glasses/hint-decision`: 인증된 계정의 설정을 확인하고 실행 중인 로컬 JEV의 choice 연산으로 후보를 분류한다. 일반 memory-choice의 기준을 변경하지 않으며 힌트별 기준을 요청마다 전달한다. 별도 생성형 LLM으로 판별하지 않는다.
- `hint-gate.mjs`: 전사와 독립된 대기열, 최대 한 개의 최신 대기 항목, 4초 판별 간격, 15초 후보 쿨다운, 30초 유효 기한, 최근 2분 문자 3-gram 중복 억제를 담당한다. 임베딩을 통한 주제 변화·의역 중복 판별은 아직 없다.
- 최근 60초/최대 16개 문맥을 클라이언트에 유지한다. 서버 모델 입력은 문맥 마지막 800자와 발화 마지막 600자로 더 제한하며 토큰 길이 초과 시 문맥 없이 발화 마지막 300자를 재시도한다.
- 한국어 기준의 JEV 점수·차이 임계값으로 후보를 선별한다. '불명확할 때 작은 LLM 추가 판별'은 구현하지 않고 생략한다. 균형 기본 점수 0.50·차이 0.08, 조용하게 0.65·0.15, 적극적으로 0.35·0.03은 초기 조절값이지 교정된 확률이 아니다.
- 기존 채팅 API에 `glasses_hint: true`로 전달한다. 서버는 private 필드를 제거하고 읽기 전용 도구만 광고·실행 가능하게 하며 일반 채팅 세션 연결·취소·장기 기억 자동 저장을 건드리지 않는다. 계정의 검색·메모리 비활성 설정은 존중한다. 확정 전사 저장은 계속된다.
- 생성된 힌트는 완성 후 유효 기한을 다시 확인한 뒤 표시한다. `HINT_SKIP`은 표시하지 않는다. 힌트는 자동 음성 재생하지 않는다. 판별 오류는 전사 실패로 취급하지 않는다.
- 실제 한국어 6개 예문에서 회상 1개는 놓쳤다. 실생활 데이터로 판별 기준을 보정하고, 의미 기반 중복·주제 변화 감지와 전사 부하에 따른 판별 빈도 조절을 후속 개선한다.

## 1.4.1 수정

최신 발화 한 문장 중심의 판별을 최근 20초/최대 6개 발화 묶음으로 교체했다. 현재 묶음 1200자와 이전 문맥 400자를 모델에 전달하며, 길이 오류 때 현재 묶음 600자로 축소한다. 마지막 맞장구만으로 앞 대화의 정보 필요성을 무시하지 않도록 지침을 변경했다. 후보끼리의 혼동과 불필요와의 혼동을 구분하고, 균형/적극 설정에서는 근접한 정보 후보를 생성 모델의 최종 생략 판정에 넘긴다.

AI 모드의 실패한 음성은 버리고 듣기를 계속하며, STT는 진행 중 1개+최신 대기 1개만 유지한다. 일반 전사·번역 모드의 보관 정책과 다르다. 내부 서버 추론 대기열에 AI 요청이 쌓이지 않도록 realtime 요청은 엔진 점유 시 429를 반환한다. 이미 실행된 추론까지 취소하는 것은 아니다.

생성 중 새 힌트는 최신 1개를 기다리게 하고 수락되지 않은 후보를 이미 표시한 것으로 간주하지 않는다. 판별 TTL 45초, 표시 TTL 90초, 생성 제한 75초로 나눴다. 직접 질문이 없다는 이유로 생성 모델이 무조건 생략하지 않도록 유형별 설명 작업을 지정했다. 글자 밝기 조절은 SDK에서 가능하지만 자동 감광과 배터리 절감 검증은 별도 작업이다.

## 1.4.2 지식 명칭과 표시 정리

필요성을 드러내는 질문을 기다리지 않고 역사·유적·인물·과학 등의 지식 명칭을 소개하는 `background` 후보를 추가했다. 다중 분류에서 힌트가 없으면 JEV의 topic/none 이진 분류를 추가로 사용한다. 초기 점수 기준은 균형 0.60, 조용하게 0.75, 적극적으로 0.52이며 실제 정확도는 교정되지 않았다. 청동기 시대 단어 및 피라미드/청동기 시대를 포함한 대화 묶음은 실제 모델에서 선별됐지만, 모든 지식 명칭을 찾는 것은 아니다.

분류명은 사용자 화면용 텍스트에 넣지 않으며 모델이 분류명을 제목으로 내놓아도 힌트 본문에서 제거한다. Whisper의 불확실한 영상 마무리 문구는 음성 근거와 함께 검사해 제외한다. 또렷한 TV 말소리까지 분리하는 기능은 없다.

## 1.4.3 정보 보충 파이프라인

전사를 받은 단일 생성 모델이 요약으로 끝내던 경로를 분리했다. `hint-enrichment.mjs`가 대화에 없는 조사 질문과 알려진 사실을 계획하고, 원문 전사 대신 그 질문·알려진 사실로 최종 정보를 요청한다. 계획 단계는 서버에서 도구·기억 주입을 비활성화한다.

`hint_research`의 web/memory 선택은 서버에서 사용자 권한을 확인한 뒤 읽기 전용 검색을 실행하고 근거를 입력에 덧붙인다. internal은 조회 없이 기존 모델의 안정된 지식을 사용한다. 검색·기억 오류는 해당 힌트에만 영향을 주며 전사는 계속된다. 최종 답은 fact/adds_information 구조를 검증하고 직접 복사·그대로 반복·일반적 요약 문구를 제거한다. 의미적으로 바꿔 쓴 모든 요약까지 검출한다고 보장하지 않으며 모델 계획의 오류도 있을 수 있다.

## 1.4.4 직접 질문 우선

확정 전사에서 명확한 의문문·정보 요청을 먼저 감지하고 힌트 선택·계획을 건너뛴다. 직접 음성 요청은 `glasses_hint_phase: direct`로 기존 서버의 읽기 전용 채팅 경로를 사용하며 원래 질문에 답한다. 검색 요청은 기존 hint_research/web 근거 조회를 사용한다. 선택적 힌트 생성 중이면 취소하고 직접 질문에 우선 답한다. 최근 직접 질문·답변 4쌍만 앱 메모리로 후속 질문에 전달한다. 일반 진술은 기존 JEV 판별·정보 보충 경로를 유지한다.

## 1.4.6 서버 프롬프트 조립 분리

일반 채팅의 retrieval 경로가 힌트에도 자동 기억·최근 웹 채팅을 주입하던 문제를 수정했다. `glasses_client` 또는 기존 `glasses_hint` 표식이 있으면 안경 전용 프로필로 처리한다. 자동 retrieval, 사용자 프로필, 스킬·일반 작업 지침을 제외하고 클라이언트의 현재 문맥과 명시적 조회 결과만 사용한다. chatharness에서도 전용 프로필은 전달된 자동 문맥 필드를 무시해 이중으로 격리한다.

내부 지식 힌트 생성과 계획에는 도구 목록을 넣지 않는다. 일반 지식 힌트에는 기억 도구를 허용하지 않고, 명시적인 기억 경로·개인 기억 질문에서만 사용자 설정에 따라 조회한다. 모든 최신 안경 응답을 일반 메모리에 자동 저장하지 않으며 전사 SQLite 저장은 유지한다. 기존 저장 데이터는 삭제하지 않는다. 디버그에 프로필과 자동 문맥 여부를 표시한다.

## 2026-11-13 Conversate 비교 검토 — 제안이며 미구현

기준: [Even 공식 Conversate 소개](https://www.evenrealities.com/conversate). 공개 페이지는 Prep Notes, 자동 AI Cues, 실시간 전사, 요약·액션 항목 저장을 설명한다. Cues는 Suggestions(명확화·검증·대화 진행 제안), Answers(업로드 자료 기반 답), Concepts(개념 설명), Bios(인물 배경)로 구분된다. 내부 모델·판별 알고리즘·성능 수치는 공개 설명만으로 확인할 수 없다. 아래는 현재 저장소 코드와 비교한 우리 앱의 개선안이며 공식 구현을 재현한다는 뜻이 아니다.

### 현재 구현에서 목적과 어긋나는 지점

1. `hintPlanPrompts`는 모든 후보를 ‘대화에 없는 조사 질문’으로 바꾸고, `hintAnswerPrompts`는 새 사실을 요청한다. reply 후보에는 ‘바로 쓸 문구’ 관점이 있지만 출력 구조는 여전히 fact/adds_information 하나다. 대화 진행에 유용한 확인 질문·반론·응답 문구를 별도 성공 기준으로 판단하지 못한다. 기존 요약 억제는 유지하되 정보 보충만을 유용성 기준으로 삼지 않아야 한다.
2. 클라이언트는 최근 20초/6개 발화와 앞 문맥을 모으지만, 서버 판별에는 최근 1200자·이전 400자만 보낸다. 장시간 대화의 목표·결정·미해결 질문을 유지하는 세션 상태와 사용자가 선택하는 사전 자료 묶음은 없다. 안경 전용 문맥 격리를 되돌려 일반 웹 기억을 자동 주입해서는 안 된다.
3. JEV 선별 후 계획 LLM과 답 생성 LLM이 순차 실행되고 웹 조회까지 붙을 수 있다. 생성 제한은 75초, 표시 유효 기한은 90초다. 이는 안전 상한이지 실제 지연 측정값은 아니다. 짧은 대화에 늦은 힌트가 끼어들 여지가 있으며 현재 `fresh()`는 시간·모드 epoch만 확인하고 주제 전환은 검사하지 않는다.
4. `HintGate`는 생성 작업 수락 시점에 최근 중복 목록과 15초 쿨다운을 기록한다. 생성 실패·최종 HINT_SKIP도 이미 처리한 후보처럼 억제될 수 있다. 입력 문자 3-gram 중복은 같은 주제의 새 질문을 억제하거나, 같은 의미의 다른 표현을 놓칠 수 있다.
5. `drainAI()`는 새 작업 시작 때 기존 답을 비운다. 자동 힌트도 ‘생각 중/조사 중’ 화면으로 바뀔 수 있다. 완성 전 후보와 표시 중인 힌트를 분리해 유용한 본문만 조용히 교체하는 편이 대화 지원에 맞다.
6. 자동 힌트는 140자에서 단순 절단한다. 현재 6줄·픽셀 폭을 활용한 문장 단위 길이 제어가 필요하다. 직접 질문의 상세 답변은 사용자가 요청한 기존 동작이므로 별도로 유지한다.

### 권장 처리 구조

확정 전사 → 현재 대화 상태 갱신 → JEV 후보 선별/우선순위 → 유형별 근거 조회·생성 → 관련성/신규성/시효 재확인 → 표시.

- 세션 상태는 현재 주제, 미해결 질문, 이미 나온 사실, 결정·할 일, 최근 표시 힌트를 보관한다. 확정 전사를 기준으로 처리하고 임시 STT를 그대로 힌트로 만들지 않는다. 원문 전사 SQLite는 계속 독립 저장한다. 상태 갱신은 매 발화마다 별도 LLM을 호출하기보다 최근 발화 묶음과 선택적 주제 요약을 이용한다.
- EmbeddingGemma 2 + JEV는 기존 로컬 후보 선별을 유지한다. 주제 유사도·중복 억제에 임베딩 재사용을 검토하되, JEV 점수를 정확도/확률로 보장하거나 임베딩만으로 사실 여부·발화자를 판정하지 않는다. 모델 점유 중에는 전사를 우선하고 힌트는 최신 후보 하나만 남긴다.
- 후보 유형은 concept / person / material_answer / suggestion / direct_answer로 나눈다. concept는 정의·시기·핵심 차이, person은 문맥으로 특정 가능한 인물 배경, material_answer는 사용자가 선택한 자료의 근거, suggestion은 지금 쓸 답변·확인 질문·논점 하나를 생성한다. 화면에는 분류명을 붙이지 않는다.
- 내부 지식으로 충분한 개념은 질문 계획과 답 생성을 한 번에 끝내는 경로를 우선 검토한다. 최신 정보·불확실한 수치·인물 동명이인 확인에만 웹 조회를 사용한다. 문서/개인 기억 조회는 사용자가 해당 세션에 선택·허용한 범위로 한정하고 근거 없이는 생략한다.
- Prep Notes는 사용자가 대화 목적과 참고 노트·문서를 선택하는 별도 기능으로 추가한다. 일반 웹 채팅의 자동 기억을 복원하지 않고 session ID와 자료 ID로 검색 범위를 제한한다. 문서 근거 위치는 휴대폰에서 확인하고 안경에는 유용한 내용만 표시한다.
- 명확한 질문의 자동 답변은 기존 요청대로 유지하되, 질문도 일반 대화의 일부일 수 있음을 고려해 상대 발화에 무조건 화면을 길게 채우는 문제를 평가한다. 발화자 구분이 없으므로 착용자의 질문이라고 단정하지 않는다. 직접 트리거·텍스트 요청은 계속 최우선이다.
- 표시 중 힌트와 생성 중 후보를 분리한다. 새 후보를 만들 때 기존 힌트를 지우지 않고, 새 본문이 검증됐을 때만 교체한다. 작업 실패는 눈앞의 오류 대신 휴대폰 상태/디버그에 남긴다. 표시 직전 최신 주제·해결 여부를 검사하고 구식 후보는 폐기한다.
- 중복/쿨다운은 성공적으로 표시한 cue ID·주제·의도를 기준으로 기록한다. 실패 반복은 별도 짧은 재시도 제한으로 다룬다. 같은 주제라도 새 질문·새 정보가 있으면 허용한다. 힌트별 유효 시간은 대화 중 응답 제안이 배경 지식보다 짧아야 하며 실측으로 조정한다.
- 자동 힌트는 6줄 안에서 완결된 1~3문장을 생성·검증하고 글자 수 강제 절단으로 문장을 끊지 않는다. 직접 답변은 기존 상세 내용·스크롤을 유지한다. 요약·결정·할 일은 별도 세션 기록 화면으로 분리하고 실시간 힌트 대신 요약을 표시하지 않는다.

### 구현 우선순위와 확인 방법

1. 사전 자료 기능보다 먼저: 유형별 출력, 기존 힌트 유지, 성공 표시 기준 쿨다운, 최신 주제/해결 여부 재검증. 현재 잘못 개입하거나 늦게 표시되는 문제를 줄이는 단계다.
2. 현재 대화 상태와 선택형 Prep Notes를 연결한다. 기존 전용 프롬프트 격리와 계정별 검색 권한을 유지한다.
3. 회의 종료 후 요약·결정·할 일을 세션별로 저장한다. 백그라운드 갱신은 STT와 힌트 처리 부하를 측정한 뒤 추가한다.

고정 한국어 대화 재생 세트로 ‘피라미드/청동기 시대 개념’, ‘동명이인 인물’, ‘자료에 있는 수치’, ‘완곡한 거절 제안’, ‘명확한 직접 질문’, ‘이미 설명한 개념’, ‘주제 전환’, ‘TV 소리/잘못된 STT’, ‘검색 실패/추론 지연’을 비교한다. 후보 발생→표시 지연(p50/p95), 유용한 힌트 비율, 필요한 힌트 누락, 반복·구식 힌트 비율, STT 지연·음성 폐기량을 기록한다. 실제 측정 전 Conversate와 동등한 품질·속도를 주장하지 않는다. 이번 검토에서는 동작 변경이나 서버 재배포를 하지 않았다.


## 1.4.9 적용 현황

위 검토의 첫 단계로 JEV 이후 단일 생성 경로와 유형별 개념/인물/응답 제안을 적용했다. 웹·기억 조회가 필요한 후보만 두 단계로 처리한다. 상시 LLM 분류·요약은 추가하지 않았다. 기존 힌트 유지, 성공 표시 기준 중복/쿨다운, 생성 간격 제한, 완결 문장 표시, 시간·주제 표현 기반 구식 후보 폐기를 구현했다. 현재 세션의 최근 표시 힌트를 생성 입력에 제공한다. 의미적 주제 상태·미해결 질문 추적, Prep Notes, 종료 후 요약은 후속 단계다. 어휘 기반 주제 검사는 의미 모델을 대체하지 않는다.
